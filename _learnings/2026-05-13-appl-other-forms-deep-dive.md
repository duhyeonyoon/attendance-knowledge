## 큰 발견

### 1. Cancel 컨트롤러 존재 패턴이 둘로 나뉨
| 신청서 | Cancel 별도 컨트롤러 |
|------|------|
| 사전 휴일근무 / 사전 연장·야간 / 재택 / 기타근무 / 휴가 | ✅ 존재 |
| 대체근무 / 근무계획 변경 / 근무내역 변경 | ❌ 없음 (메인의 `/cancel` 액션만) |

→ Cancel 컨트롤러가 있는 것들은 "결재 완료 후 취소"가 별도 워크플로우 (취소 신청서 발행). 없는 것들은 단순 액션. **이 차이가 왜 있는지 [TBD]**.

### 2. 재택 컴포넌트는 `HomeWork.tsx`, DB는 `TM_WORK_FOR_HOME_*`
영문 명명 컨벤션 불일치 (`Home` vs `WorkForHome`). 검색 시 주의.
별도로 `TM_RMT_WORK_*` 테이블 그룹도 존재 — 두 그룹 관계 [TBD].

### 3. `TM_WORK_GRP_CHG_APPL` 사용처 재확인
근무그룹 영역 deep-dive에서 "근무계획 변경/대체근무 신청서에서 사용"이라고 했는데, 이번에 확인하니 정확히 그 두 신청서에서 사용 중. cross-reference 강화됨.

### 4. 기타근무 신청서 = 신청서 중 가장 복잡
- 기간 신청 + 일자별 토글 (휴일/휴무일도 토글로 포함 가능)
- 3단계 유효성 (기간 / 일자별 / 요청)
- 유형별 코멘트/파일 첨부 필수 여부
- 종일 vs 직접 입력 옵션
- 어드민 직접 등록 별도 다이얼로그 (`AdminDirectOtherWorkDialog`)
- 출퇴근 위젯에 요약 표시 (2건+ 아코디언)
- 재택 Chip과의 표시 우선순위

→ 별도 deep-dive 가치 있을 정도로 큰 영역이지만, 표준 패턴 + cross-link로 묶음 처리 가능했음

### 5. 대체근무 8가지 불가 케이스
대체근무는 짝(swap) 신청 + 다른 신청서들과 상호 배타라서 유효성이 가장 많음:
- 정산기간/근무그룹/스케줄/대체근무 허용 등 모두 검증
- 근무계획 변경 신청과 상호 배타 (둘 중 하나가 요청중이면 다른 쪽 불가)

### 6. 근무계획 변경의 알려진 버그
QA에 🚨 표시된 임시 동작 — 근무그룹 변경 시 개인스케줄 잔존 (국인님 처리 예정). 향후 해소 시 본문 업데이트 필요.

### 7. 표준 패턴의 한계
표준 패턴은 빠른 정리에 유용했지만, 각 신청서의 특수 룰(특히 기타근무의 3단계 유효성, 대체근무 짝 짓기, 근무계획 변경의 우선순위)은 별도 시간 들여 정리 필요. 묶음 문서가 너무 커지지 않게 차이점만 집중.
