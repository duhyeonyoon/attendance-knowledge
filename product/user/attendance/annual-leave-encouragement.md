```
[어드민이 연차촉진 작업 생성]
   ↓ (대상자로 지정된 경우)
[사용자에게 미사용 연차 통지서 발송]
   ↓ 본 화면에서 조회/서명
[연차 계획서 작성]
   ↓ 본 화면에서 작성/확정
[어드민이 사용시기 지정 통보 (선택)]
   ↓ 본 화면에서 통보 문서 + 알림 팝업
```

## 사용자 측 동작 흐름

### 1단계: 그룹 표시

- **어드민에서 연차촉진 그룹 생성 시** → 상단 셀렉트에 노출
- 사용자가 셀렉트로 자신이 속한 연차촉진 그룹 선택

### 2단계: 미사용 연차 통지서 (어드민이 통지 실행 후)

- **미사용 연차 통지 문서 조회** + **확인(제출)**. ~~서명~~ → **(2026-11-05 Slack 확인) 통지서는 서명란 없음.** 서명이 필수인 문서는 **연차 사용 계획서뿐**이고 미사용 연차 통지서·사용시기 지정 통보서는 서명 없이 문서 확인으로 처리 — MVP 결정 Slack #sq-time 2025-06-10 "프로세스상 서명이 필수여야 하는건 연차사용계획서… 나머지 통지서들은 상태제어에 서명여부 반영하지 않음" (https://hcgtheplus.slack.com/archives/C04QC2RJJBU/p1749527404507349?thread_ts=1749444345.441229&cid=C04QC2RJJBU), 양식 확정 #sq-sys 2025-06-26 "미사용연차 통지서(서명 X) / 연차사용계획서(서명 O) / 사용시기지정통보서(서명 X)" (https://hcgtheplus.slack.com/archives/C04V0TUNRGV/p1750929103598859?thread_ts=1750903393.871339&cid=C04V0TUNRGV). 법적 서명 필수 아님, 실무상 계획서·노무수령거부만 서명 관행(#sq-time 2025-04-16)
  - 상태 칩: 통지서·통보서 = `미서명`(UNSIGNED, 미열람) → `확인완료`(CONFIRMED, 확인일시 기록) — 칩 라벨은 "미서명"이지만 실제 동작은 열람·확인 (`be:service/encouragement/UserEncouragementService` `unusedNotificationConfirmedDate`). 계획서 = `미작성` → (확정) `미서명` → (서명) `확인완료`
  - 양식은 회사별 전자문서 양식이라 고객사가 통지서에 서명란을 추가하는 것은 가능하나, 서명 여부는 촉진 상태에 반영되지 않음(2025-06-10 "서명 필수여부 속성에 따라 상태제어가 달라져야 함 → 이후 과제")

### 3단계: 연차 계획서 작성

- 미사용 연차 통지 **확인** 후 → **연차 계획서 작성 문서** 노출 (~~서명 후~~, 2026-11-05 정정)
- **연차 계획서 미작성 상태 + 클릭** → 연차 계획 작성 다이얼로그 (`annual_leave_encouragement_plan_dialog/`)
- **계획서 확정** → 연차 사용 계획에 작성한 계획 표시
- 확정 후 → 연차 계획서 작성 문서 **조회 + 서명** 가능

### 연차 계획 작성 다이얼로그 상세 (2026-11-05 코드 확인)

`pp:src/components/attendance/annual_leave_encouragement/contents/annual_leave_encouragement_plan_dialog/` (라벨 `ANNUAL_LEAVE_ENCOURAGEMENT.*`)

- **상단 요약**: 총 연차 · 의무 사용 연차 · 사용 연차 · **촉진 필요**(시간/일) + 촉진 기준일. 툴팁 "의무로 사용해야 하는 연차로, 해당 일수내 미사용 일수에 대해 사용을 촉진합니다.", "실제 사용 일수와 차이가 있을 수 있습니다. (촉진 기준일: …)", 분할촉진 시 "분할촉진 시에는 다른 회차에서 사용한 연차도 촉진 필요 일수에 반영됩니다…"
- **사용시기 행 목록** (행 = 사용일 + 사용시간[종일 체크 또는 시·분]):
  - 임시저장 계획이 없으면 **촉진 필요 시간 ÷ 1일 표준근로시간(`cenDdWorkTime`)** 만큼 종일 행을 미리 생성, 나머지 시간은 마지막 행에 부분 시간으로 생성
  - [전체 종일 적용], [항목 추가], 행 삭제
  - 안내(ⓘ) "연차 계획서 작성은 휴가 요청과 무관하며 실제 사용할 휴가는 휴가 요청을 통해 등록하시기 바랍니다."
- **버튼**: [임시저장] ("임시저장을 완료했습니다.") / [확정] → 컨펌 "작성한 연차 계획서를 정말 확정하시겠습니까? 확정 후 문서로 이동하여 서명까지하면 연차촉진 프로세스를 완료합니다." → "확정을 완료했습니다." / 닫기 시 "작성 종료 — 정말 닫으시겠습니까?"
- **검증** (확정 시 클라이언트 + 서버 `failureReason`):
  | 상황 | 문구 |
  |------|------|
  | 날짜·시간 미입력 | "날짜 및 시간을 입력해주시기 바랍니다." / "날짜를 입력해주시기 바랍니다." / "시간을 입력해주시기 바랍니다." |
  | 같은 날짜 중복 | "동일한 날짜가 존재합니다. 날짜를 확인해주시기 바랍니다." |
  | 사용기간 밖 날짜 | "연차 사용기간 내의 날짜만 선택할 수 있습니다." |
  | 휴일·휴무일 (서버) | "휴일 및 휴무일은 신청이 불가합니다." |
  | 합계 > 촉진 필요 시간 | "촉진 필요 시간을 초과하였습니다." |
  | 합계 < 촉진 필요 시간 | "남은 시간을 모두 적용 후 확정 가능합니다." |
  | 사용시간 0 이하 (서버) | "사용시간은 0보다 커야 합니다." |
  | 촉진일수 불일치 (서버) | "촉진일수와 사용계획의 총 사용시간이 일치하지 않습니다." |
  | 기간 만료 | "기간이 만료되어 계획서 작성을 할 수 없습니다." |
- → **합계가 촉진 필요 시간과 정확히 같아야 확정 가능**

### 4단계 (선택): 사용시기 지정 및 통보 (어드민 측)

어드민이 사용시기 지정 통보 실행 시:
- **사용시기 지정 통보 문서** 노출
- **연차 사용 계획에 어드민이 지정한 계획 표시**
- **유저 화면에서 통보 날짜에 통보 알림 팝업**
  - **확인 누르기 전까지 다른 웹페이지 요소 클릭 불가** (강제 모달)

## 비즈니스 룰

1. **사용자 측은 어드민이 트리거하는 것에 반응**: 통지 수신 → 통지 확인 → 계획 작성 → 확정 → 계획서 서명 → 통보 수신 (서명은 계획서만, 2026-11-05 정정)
2. **계획서 확정 전까지** 연차 계획 수정 가능
3. **사용시기 지정 통보 알림 팝업**: **강제 모달** (확인 전 다른 작업 불가)
4. **연차 사용 여부는 연차에만 카운트** (`leave-domain.md` § C-5와 일관)
5. **노무수령거부 팝업** 4가지 조건 (`leave-domain.md` § C-5)
