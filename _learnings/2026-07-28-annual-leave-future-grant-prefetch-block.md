# 연차 미래 생성분 선차감 방지 — 재현 조건 정리

작성: 2026-07-28 / 계기: 노진철님 Slack 질문(테스트 절차 검증)

## 문구가 나오는 지점 (BE)

`be:com/hcg/optimiz/time/service/leaveuse/CalcLeaveService`

| 라인 | 조건 | 문구 |
|---|---|---|
| 1010 | `overUsePmit == false` (초과사용 불허 또는 한도 0) | **생성된 휴가보다 더 많이 사용할 수 없습니다.** |
| 1015 | 초과사용 허용이지만 한도 소진 | 생성된 휴가에서 N시간 까지만 초과사용이 가능합니다. |
| 1091 | `matchAnnualByUsagePeriodOnly && isNormalAnnualLeave` + 사용일을 커버하는 양수 생성분이 **하나도 없음** | **생성된 휴가보다 더 많이 사용할 수 없습니다.** |

→ 같은 문구가 두 경로(1010 / 1091)에서 나온다. 재현 절차 설계 시 어느 경로를 노리는지 명시해야 함.

## 매칭 규칙 (핵심)

- `matchAnnualByUsagePeriodOnly = true` (신청·승인 차감): 정상연차 생성분은 **사용기간 포함 여부로만** 매칭. → 미래 생성분 선차감 차단.
- `false` (생성·재계산·정산): `귀속연도 일치 || 사용기간 포함` (기존 동작 보존).

## 회귀 재현 필수 조건

수정 전 매칭이 `귀속연도 일치 || 사용기간 포함`이었으므로,
**신청일의 회계연도 == 미래 생성분의 귀속연도**일 때만 예전 버그가 재현된다.
→ 사용기간이 회계연도 경계를 넘어야 하므로 **입사일 기준 연차(`ANL_GEN_STD='D'`)** 필수.
회계연도 기준이면 귀속연도 = 사용기간 연도라 이 케이스가 성립하지 않는다.

## 표준 재현 절차 (회귀 테스트와 동일)

전제: `ACC_YY_STA_MM_DD='0101'`, `ANL_GEN_STD='D'`, `OVER_USE_PMIT_YN='N'`, 입사일 08-26

1. 2025 귀속분 생성 — 사용기간 20250826~20260825, 1일(480분)
2. 2026 귀속분 생성 — 사용기간 20260826~20270825, 1일 (아직 시작 안 함)
3. 20251020에 1일 사용·승인 → 2025 귀속분 잔여 0
4. **20260708**로 1일 신청 → 거절 (회계연도 2026 = 2026 귀속분 귀속연도, 사용기간은 2025 귀속분 안)
5. 대조군: 20260901(2026 귀속분 사용기간 시작 후) 신청 → **정상 통과해야 함**

## 초과사용 허용 시 주의

- 한도 여유 있음 → 사용일을 커버하는 생성분(=현재 귀속분)에 초과분을 얹어 **통과**한다. 거절 안 됨.
- 한도 소진 → 1015의 다른 문구가 먼저 나옴.
→ 초과사용 소진 스텝을 넣으면 목표 문구가 안 나온다.
