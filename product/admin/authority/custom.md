# 서브어드민 권한

> **메뉴** 근무관리 › 권한 › 서브어드민 권한  
> **URL** `/attendance/authority/custom`  
> **원본** `product/_legacy/admin-system-entry.md`

권한 모델 전체(4단계 계층, 권한 결정 흐름)는 [모듈 설정·권한 공통](../module-setting/overview.md)을 보세요.

*원본 섹션: #4-2. 서브어드민 권한 (L103–180) — 가장 복잡*

**구조**: 권한그룹 (단위) → 담당자 (사람) → 권한 범위 (대상)

## 메인 페이지

- 컬럼: No / 그룹명 / 회사 / 담당자 (`ad:src/hooks/authority/useAuthorityGroupColumn.tsx`, 근무에서는 인사 모듈 컬럼 제외)
- 목록 없으면: "권한그룹을 생성합니다." 안내
- [권한그룹 추가]:
  - dialog → 그룹명 + 그룹 설명 입력 → 추가 (**둘 다 필수**: "그룹명이 없습니다." / "그룹 설명이 없습니다.", `ad:src/components/shared/authority/custom/DialogContentCreateAuthGroup.tsx:74-81`)
  - 추가 완료 시 dialog 닫힘 + 목록 갱신
- **필터**: 그룹명 / 담당자 (클라이언트 측 필터)
  - **(2026-11-05 해소) QA의 "그룹 모듈" = 화면 라벨 "그룹명" 필터.** 옵션은 등록된 권한그룹명 목록이며 선택한 그룹만 목록에 남김. 코드 변수명이 `moduleOptions`/`selectedModule`이라 "모듈"로 불렸을 뿐 모듈(근무/인사 등) 필터가 아님 (`ad:src/hooks/authority/useAuthorityGroup.ts:32-34`, `ad:src/locales/ko/sharedComponentAuth.json` `system.AuthGroupFilter.groupNameLabel`)
- 클릭 → 상세 페이지

**← 버튼 (뒤로 가기)**:

- 담당자 없음 → 활성 (삭제 가능) → "권한그룹 삭제" 컨펌 "설정한 권한그룹을 삭제합니다."
- **담당자 있음 → 비활성** (삭제 불가), 툴팁 "담당자를 설정한 권한 그룹은 삭제할 수 없습니다."
  - 권한 기간이 끝난 담당자도 "담당자 있음"으로 판정 (`be:service/auth/TimeAdminAuthGroupSettingService.java:384` TODO — 활성 담당자 기준으로 바꿀 예정)
  - **(2026-11-05 Slack 확인 — 기획 ≠ 구현)** 원래 기획은 "**활성 담당자**(권한 기간이 오늘과 겹치는 담당자)가 있을 때만 삭제 버튼 비활성", 권한 종료일이 지난 담당자는 목록에서 흐리게(30%) 표시 — Slack #sq-sys 2024-07-15 (https://hcgtheplus.slack.com/archives/C04V0TUNRGV/p1721051567472709?thread_ts=1721051333.063949&cid=C04V0TUNRGV). 현재 구현은 종료된 담당자까지 막으므로 구현 누락. 종료된 담당자는 수정 불가, 삭제 후 재등록만 가능(릴리즈 노트 #070 코멘트 2026-10-27)

## 카드 2: 담당자 설정

**담당자 현황 목록**:
- 담당자 없음 → "담당자를 추가합니다." 문구
- **권한 종료일이 지난 담당자** → **투명도 0.3** (흐리게)
- 삭제 컬럼 외 영역 클릭 → **담당자 설정 페이지** 이동
- 삭제 컬럼 X 버튼 → "삭제" 컨펌 → 삭제
- [담당자 추가] → "담당자 추가" dialog
- "담당구성원" 필드: 권한범위 지정 후 범위내 구성원이 생기면 "??? 등 ?명" 표시

**담당자 추가 dialog**:
- **활성 상태 구성원만** 추가 가능
- 구성원 선택 + 권한 기간 "시작일" 입력 시 추가
- 완료 후 → **담당자 설정 페이지로 이동**

## 담당자 설정 페이지 (가장 복잡)

**진입 시 상태**:
- 추가 모드: 이미 등록한 담당자 이름 + 권한 기간 입력 상태
- 수정 모드: 우측 상단에 **삭제, 취소, 저장** 버튼
- 추가 모드: 우측 상단에 **취소, 저장** 버튼

**페이지 이탈** (← 또는 [취소] 버튼):
- 변경 없음 → 즉시 상세 페이지 이동
- 변경 있음 → "알림" 컨펌 → 확인 시 이동

**저장 시 밸리데이션** (`ad:src/components/attendance/authority/custom/detail/detail/index.tsx:285-325`):
- 담당 범위 또는 구성원 미추가 → "담당 범위 지정 또는 구성원을 직접 추가합니다."
- 권한 기간 시작일 삭제 → "권한 시작일을 입력합니다."
- 시작일/종료일 형식 오류 → "시작일이 유효하지 않습니다." / "종료일이 유효하지 않습니다."
- 종료일 < 시작일 → "종료일은 시작일 이후의 날짜로 입력합니다."

**담당 범위 ("회사 / 조직" 행 단위)** (`ad:src/components/shared/authority/custom/manager_setting/CompanyAndOrganizationSelect.tsx`):
- 안내 문구: "담당하는 회사/조직을 선택합니다. 회사/조직 필터로 특정 회사/조직에 속한 구성원을 담당할 수 있습니다."
- 한 행 = [담당할 회사] - [담당할 조직(다중 선택, "전체 조직" 옵션 포함)]
- 첫 행 회사에만 "전체" 옵션. 회사 "전체" 선택 시 조직 선택 disabled + [+] 비활성
- 같은 회사는 한 번만 선택 가능 ("이미 선택한 회사입니다." 툴팁)
- 담당 범위 선택 → "범위내 구성원"에 자동 노출
- [+] 버튼으로 행 추가, 2개 이상 시 우측 삭제 아이콘

> ⚠️ **근무그룹 담당 범위 옵션은 여전히 주석 처리** (`AuthorityScopeConfig.tsx:16, 133-141`). 코드 주석상 "특정 고객사에서만 불필요한 것인지 기획에서 안 쓰기로 확정한 것인지 결론이 안 남" — 미확정 상태. (2026-11-05 Slack 검색: 2024-09-05 기획 회의에서 담당 범위에 근무그룹을 **추가**하기로 한 기록과 범위 내 구성원 갱신 고민(2024-09-30)만 있고, **숨김 결정·사유 논의는 없음**)

**범위내 구성원 (3가지 카테고리)**:

```
[담당 구성원] 탭                    [추가 구성원] 탭                [제외 구성원] 탭
   - 범위 선택으로 들어온 자          - 명시적으로 추가한 자          - 명시적으로 제외한 자
   - 추가 구성원도 표시됨            - 추가/삭제 가능                - 복구 가능
```

**구성원 추가 동작**:
- 추가하면 **"담당 구성원" + "추가 구성원"** 양쪽 등록
- **비활성 구성원도 조회됨** (담당 범위 내)
- 구성원 추가 dialog에서 **이미 추가된 구성원** → disabled + 툴팁 "이미 선택한 구성원입니다."

**제외 동작**:
- 담당 구성원 (추가 구성원 아닌 자) 체크박스 → [제외] 버튼 활성화
- 제외 → 담당 구성원에서 삭제 + 제외 구성원에 추가

**복구 동작** (제외 구성원 탭):
- 체크 + [복구] 버튼 또는 + 버튼 → 제외 구성원 복구
- **복구 시 분기**:
  - 담당 범위에 존재하면 → 담당 구성원에 다시 포함
  - 담당 범위에 없으면 → **삭제** (단순 제거)

**추가 구성원 삭제** (추가 구성원 탭):
- 체크 + [삭제] 또는 X 버튼 → "구성원 삭제" 컨펌 → 삭제
- 담당 구성원 탭에서도 사라짐

## 카드 3: 권한 설정

**근무관리 업무권한** — 표 컬럼: 구분 / 상세 분류 / 권한. "구분" = 업무권한 그룹, "상세 분류" = 메뉴 단위 권한. 그룹은 4종이 아니라 **5종**(과거 데이터 관리 추가). (2026-11-05 확인: `be:constant/CONST_TIME_AUTH.ADMIN_AUTH_GROUP`, `be:constant/JOB_AUTH_TM`, `TM_JOB_AUTH` 시드 migration, `be:resources/json/timeAdminMenu.json`의 메뉴별 `allowedAuths`)
