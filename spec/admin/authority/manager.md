> **URL** `/attendance/authority/manager`
> **사용자** 어드민(근무 총괄)

## 1. 개요
직책을 묶은 **직책그룹** 단위로 권한을 설정하는 화면입니다. 직책그룹에 포함된 직책을 보유한 구성원(및 조직장 조건에 해당하는 구성원)에게 권한이 자동으로 부여됩니다. 담당자를 명시적으로 지정하는 방식은 [서브어드민 권한](./custom.md)에서 다루며, 전체 권한 모델은 [모듈 설정·권한 공통 정책](../module-setting/overview.md)을 봅니다.

## 2. 화면 구성
| 영역 / 탭 | 구성 요소 | 설명 |
|---|---|---|
| 메인 | 직책그룹 리스트 | 그룹명, 포함 직책, 인원수, 삭제(X) 아이콘 |
| 메인 | 미부여 직책 | 어떤 직책그룹에도 속하지 않은 직책 |
| 상세 | 권한 설정 섹션 | 직책 그룹명, 포함 직책, 조직장 조건, 권한 범위, 권한 표. [수정] 후 편집, [취소] / [저장] |
| 상세 | 직책자 현황 | No · 이름 · 사번 · 회사 · 조직 · 조직장 여부 · 직책, 회사 / 이름 필터 |

## 4. 정책 · 비즈니스 룰
1. 직책자 권한은 직책 기반으로 **자동 부여**되며, 직책그룹을 변경하면 해당 직책 보유자의 권한이 즉시 바뀝니다.
2. 하나의 직책은 직책그룹에 속하거나 "미부여 직책"으로 남습니다. 그룹에 추가·저장하면 미부여 목록에서 빠집니다.
3. 포함 직책 칩은 선택 순서와 무관하게 기본 정렬 순서로 표시됩니다.
4. "구성원 근무 현황, 구성원 휴가 현황" 권한이 있어야 사용자 화면의 구성원 근무 / 구성원 휴가에서 타인 데이터를 조회할 수 있고, "근무스케줄 작성" 권한이 있어야 근무스케줄을 작성·수정할 수 있습니다.
5. 하나의 직책은 하나의 직책그룹에만 포함될 수 있습니다.
6. 직책그룹은 소속 직책 보유자가 있어도 삭제할 수 있으며, 삭제 시 권한이 즉시 회수됩니다.
- **직책자 권한이 매니저 기능의 전부**: 별도 매니저 권한은 없고, 조직장으로 지정만 해서는 권한이 생기지 않습니다. 개인 단위 예외 부여도 불가합니다 (기획 확인 2026-11-05).
- **권한과 무관한 화면**: 구성원 근무의 '일정' 탭은 누구나 볼 수 있고, '현황' 탭과 요청 처리만 직책자 권한이 필요합니다. 근무스케줄 수정 권한도 직책자 권한으로 정해지며, 권한이 없으면 본인 스케줄만 읽기 전용으로 봅니다.

## 5. 메시지 · 예외 처리
| 상황 | 화면 메시지 / 처리 |
|---|---|
| 수정 중 [취소] | 초기값으로 복원 |
| 직책그룹 삭제 확인 | "삭제 요청" — "직책자 권한 유형 '(그룹명)' 삭제하시겠습니까?" → "직책자 권한 유형 '(그룹명)' 삭제했습니다." |
| 그룹명 미입력 | "직책 그룹명을 입력합니다." |
| 포함 직책 미선택 | "직책을 1개 이상 선택합니다." |
| 변경 없이 저장 | "변경사항이 없습니다." |
| 그룹 생성 / 수정 완료 | "직책자 유형을 생성했습니다." / "직책자 유형변경이 완료되었습니다." |
| 다른 그룹에 이미 있는 직책 포함 | "권한 그룹에 맵핑되는 대상 직책은 중복될 수 없습니다. (직책명)" |
| 포함 직책이 말줄임 처리됨 | 마우스 오버 시 툴팁 |
