# 고객사 근무·휴가 세팅 가이드 (운영 플레이북)

> **목적**: 고객사가 자사 근무/휴가 제도를 설명하거나 관련 문서를 제공했을 때, talenx에서 어떻게 세팅하는지 판단하고 안내하기 위한 내부 지식 문서.
>
> **사용 방법**: 고객사 제도 내용(말로 설명, 문서 첨부, 사전 질문지 등 형태 무관)을 받으면 아래 흐름으로 분석하여 세팅 방법과 한계사항을 안내한다.
>
> **문서 구성**: 1부 근무 세팅 / 2부 휴가 세팅 / 3부 운영 공통
>
> **최종 업데이트**: 2025-05-07 (원본) / 2026-05-13 (KB 통합)
>
> **출처**: 두현님 제공 내부 문서를 KB에 통합. 기존 KB 문서들과 cross-link 추가.

---

## 빠른 의사결정 흐름 (TL;DR)

```
[고객사 제도 설명 받음]
   ↓
[Step 1: 근무제 유형 판단] (5종 중 분류)
   ├─ 출퇴근 시간 고정 → 유형 1: 고정근무
   ├─ 출근 시간만 선택 → 유형 2: 시차출퇴근
   ├─ 코어타임/자율 + 정산기간 → 유형 3: 선택적/탄력적 근로
   ├─ 출퇴근 기록 없이 인정 → 유형 4: 간주/재량근로
   └─ 조별 순환 근무 → 유형 5: 교대근무
   ↓
[Step 2: 근무그룹 + 근무 템플릿 세팅] (KB 참조)
   ↓
[Step 3: 휴가 세팅 — 별도 휴가그룹]
   ↓
[복합 케이스 / 한계 항목 → BizOps 확인]
```

> **복수 유형 혼재 시** (예: 사무직 = 선택적 / CS팀 = 교대): **유형별 근무그룹 분리 생성**

# 1부. 근무 세팅

## Step 1. 제도 유형 판단

고객사 설명에서 아래 키워드와 조건을 확인하여 근무 유형을 판단.

| 판단 기준 | 해당 유형 |
|---|---|
| 출퇴근 시간 고정, 별도 유연성 없음 | → **유형 1**: 고정근무제 |
| 출퇴근 시간만 선택 가능, 하루 근무시간은 동일 | → **유형 2**: 시차출퇴근제 |
| 출퇴근 자유 또는 코어타임 있음, 정산기간 기준 연장 계산 | → **유형 3**: 선택적/탄력적 근로시간제 |
| 출퇴근 기록 없이 소정근로 자동 인정 | → **유형 4**: 간주/재량근로제 |
| 조별 순환 근무, 주간/오후/야간 교대 | → **유형 5**: 교대근무제 |

> **복합 제도 주의**
> - "선택적 근로시간제 + 보상휴가제" → 유형 3 + 휴가 설정에서 보상휴가 별도 (`KB:product/admin/leave/overview.md` § A-3)
> - "고정근무 + 재택 허용" → 유형 1 + 출근지 관리에서 재택 허용 ON (`KB:product/admin/work/base-setting.md` § 3)
> - "3조3교대 + 비번일 2조2교대" → 유형 5 + 패턴별 템플릿 분리 구성

---

## Step 2. talenx 세팅 구조

모든 근무 세팅은 아래 2단계 구조.

```
[1단계] 근무 설정 (어드민 #5) — 회사 공통 마스터
  - 회계연도 시작일 / 한 주의 시작요일       → KB:product/admin/work/base-setting.md § 1
  - 회사 공통 휴일 (법정 + 약정)              → § 2
  - 회사 공통 출근지 (GPS 반경 / IP)          → § 3
  - 기타근무 항목 (출장, 외근, 교육)          → § 5
  - 근무 템플릿 (= 근무 계획의 종류)          → § 4

[2단계] 근무그룹 설정 (어드민 #6) — 같은 제도 적용 구성원 단위
  - 근무제 유형 (고정 / 유연 / 간주 / 스케줄)
  - 표준근로시간(일) / 정산기간 / 정산기준일
  - 출퇴근 기록 방식
  - 연장 / 야간 / 휴일근무 허용 방식 (P/A/N)
  - 그룹 스케줄 (요일별 템플릿 지정)
  - 구성원 배정
                                              → KB:product/admin/work/group-setting.md
```

> ⚠️ **근무그룹은 생성 후 그룹명·메모를 제외한 설정값 변경 불가** (`KB:product/admin/work/group-setting.md` § "확정 후 제약"). 세팅 전 고객사 제도를 정확히 파악한 후 생성. 변경 필요 시 talenx SC 문의.

> **용어 정리** (`KB:domain/glossary.md`):
> - **근무 스케줄 = 근무 계획** (동의어)
> - **근무 계획의 종류 = 근무 템플릿** (재사용 가능 타입)

## 유형 1. 고정근무제

### 판단 기준
- 출퇴근 시간이 명시적으로 고정 (예: 09:00~18:00)
- 유연성·코어타임·정산기간 언급 없음
- "표준 근무시간", "정해진 근무" 등의 표현

### 세팅 방법

**근무 템플릿** (`KB:product/admin/work/base-setting.md` § 4)
- 근무구분: `근무일`
- 출근시간: `정해진 시각에 출근` → 고정 출근시각 입력
- 퇴근시간: `하루 근무시간이 지나면 퇴근` → 소정근로시간 입력 (보통 8시간)
- 휴게시간: `고정` → 점심시간 입력 (예: 12:00~13:00)
- 지각 기준시각 / 출근인정시각 설정 (필요 시)

**근무그룹** (`KB:product/admin/work/group-setting.md`)
- 근무제 유형: `고정근무`
- 표준근로시간(일): 8시간
- 정산기간: 1개월 (또는 1주)
- 기본 근무시간 기준: `출퇴근 기록`
  - 출퇴근 모두 필수 → `출퇴근 필수`
  - 출근만 기록 → `출근만 필수` (퇴근 자동 간주)
- 연장시간 관리 방식
  - 퇴근시간 이후 연장 → `계획된 퇴근 시간 이후부터 연장`
  - 하루 누적 기준 초과 → `하루 근무시간이 기준을 넘어가면 연장`

**그룹 스케줄** (`KB:product/admin/work/group-setting.md` § "그룹스케줄")
- 월~금: 고정근무 템플릿 / 토: 휴무 / 일: 휴일
- 반복 설정: `휴일만큼 건너뛰고 적용`

### 자주 나오는 케이스

| 케이스 | 세팅 포인트 |
|---|---|
| 사전 승인된 연장만 허용 | 연장근무 허용: `승인 시에만 연장 가능` (`otPmitCd === "A"`, `KB:product/admin/work/group-setting.md` § "근무 허용 코드") |
| 지각/조퇴 관리 필요 | 근무 템플릿 추가 설정에서 지각/조퇴 기준시각 입력 |
| GPS 기반 출퇴근 제한 | 근무그룹 출근지 관리: GPS 좌표 활성화 + 반경 설정 (`KB:product/user/home/checkin-widget.md` § GPS) |
| 당직근무 스케줄 별도 운영 | 당직용 템플릿 별도 생성 후 해당 구성원 스케줄에 수동 적용 |
| 재택 병행 허용 | 출근지 관리: 재택근무 허용 ON (`workForHomePmitYn`) |

### 한계사항
- 휴일 매년 반복 설정 기능 개발 중 → 매년 수동 등록 필요
- IP 기반 출퇴근 제한 개발 중 (현재 GPS만 가능)
- 연장근무 `불가` / 휴일근무 `불가` 옵션 개발 중

## 유형 2. 시차출퇴근제

### 판단 기준
- "출근 시간 선택 가능", "시차출퇴근", "08시/09시/10시 출근 중 선택" 등
- 하루 근무시간은 동일 (8시간), 시작 시간만 다름
- 정산기간 기준 연장 계산 언급 없음

### 세팅 방법

**근무 템플릿** — 시간대별로 각각 생성
- 예: `시차출퇴근(08시)` → 출근 08:00, 소정근로 8시간, 점심 1시간
- 예: `시차출퇴근(09시)` → 출근 09:00, 소정근로 8시간, 점심 1시간
- 예: `시차출퇴근(10시)` → 출근 10:00, 소정근로 8시간, 점심 1시간

**근무그룹**
- 근무제 유형: `고정근무` (시차출퇴근도 talenx 내에서 고정근무 유형으로 설정)
- 연장시간 관리 방식: `하루 근무시간이 기준을 넘어가면 연장`

**그룹 스케줄**
- 기본 시간대 하나 지정 후, 구성원 개별 또는 조직장이 템플릿 변경 가능 (근무계획 변경 신청서 활용 — `KB:product/user/applications/plan-change.md` § 4)

### 자주 나오는 케이스

| 케이스 | 세팅 포인트 |
|---|---|
| 코어타임 있는 시차출퇴근 | 출근시간: `자유롭게 출근` → 코어타임 시각 입력 |
| 매월 시간대 변경 허용 | 그룹 스케줄에 복수 템플릿 등록 → 근무계획 변경 신청서로 개인 변경 |
| 부서별 다른 시간대 고정 | 시간대별로 근무그룹 분리 생성 |

### 한계사항
- 선택 가능 시간대가 많을수록 템플릿 수 증가 → 관리 복잡도 상승
- 매일 다른 시간대 선택은 매번 근무계획 변경 신청 필요 → 월/주 단위 변경 권장

## 유형 3. 선택적 근로시간제 / 탄력적 근로시간제

### 판단 기준
- "코어타임 ○○~○○시", "정산기간 월 단위", "월 소정근로시간 기준"
- "일/주 단위 연장 미적용", "정산기간 합계 초과 시 연장"
- "선택적 근로", "유연근무", "자율출퇴근" 등
- 탄력적 근로시간제: "성수기/비수기", "주별 근무시간 상이", "단위기간 평균 40시간"

> **두 제도의 차이**
> - **선택적 근로시간제**: 근로자가 출퇴근 시각을 자율 결정
> - **탄력적 근로시간제**: 회사가 주별 근무시간을 계획하여 배분
> - talenx 세팅 방식은 정산기간 설정 외 거의 동일

### 세팅 방법

**근무 템플릿**
- 출근시간: `자유롭게 출근`
  - 코어타임 있으면 코어타임 시각 입력 (예: 10:00)
- 퇴근시간: `자유롭게 퇴근`
- 하루 근무시간: 소정근로시간 입력 (예: 8시간)
- 휴게시간: 고정 또는 자동 적용

**근무그룹**
- 근무제 유형: `유연근무`
- 표준근로시간(일): 8시간
- 정산기간: 제도에 따라 설정
  - 선택적 근로시간제: 1개월 (최대 3개월)
  - 탄력적 근로시간제: 2주 / 1개월 / 3개월 / 6개월
- 소정근로시간 기준: `법적기준 적용` (주 40시간)
- 연장시간 관리 방식: `정산기간의 근무시간 합계가 기본 근무시간을 넘어가면 연장`
  - 이 옵션 선택 시 출퇴근 위젯의 "예상 퇴근시간 초과" 안내문이 미노출됨 (`KB:product/user/home/checkin-widget.md` § "정산기간 vs 일별 연장근무 분기")
- 기본 근무시간 기준: `출퇴근 기록` → 출퇴근 필수

### 실제 케이스 예시 — TXR 유연근무제 운영지침

고객사가 아래와 같은 내용의 운영지침을 제공한 경우:
- 코어타임: 10:00~16:00 (점심 12:00~13:00 제외)
- 선택 출근: 08:00~10:00 / 선택 퇴근: 17:00~20:00
- 정산기간: 매월 1일~말일
- 월 소정근로시간 = 1일 8시간 × 소정근로일수
- 고정 연장 20시간 포함, 초과분은 보상휴가 1.5배 지급

**세팅 방향**:
- 근무그룹 유형: `유연근무`, 정산기간 1개월
- 근무 템플릿: 출근 자유, 코어타임 10:00 입력, 퇴근 자유, 소정근로 8시간, 점심 고정 1시간
- 연장시간 관리: `정산기간 합계 초과 시 연장`
- 연장근무 허용: `승인 시에만 연장 가능` (사전 승인 원칙, `otPmitCd === "A"`)
- 보상휴가: 휴가 설정에서 보상휴가 유형 별도 생성 → 인사팀이 월 단위 일괄 지급 (`KB:product/admin/leave/non-annual-management.md` § C-2 "수동 휴가 지급")

### 자주 나오는 케이스

| 케이스 | 세팅 포인트 |
|---|---|
| 코어타임 설정 | 템플릿 출근: `자유롭게 출근` → 코어타임 시각 입력 |
| 정산기간 3개월 | 근무그룹 정산기간 3개월, 정산기준일 설정 |
| 연장 사전 승인 필요 | 연장근무 허용: `승인 시에만 연장 가능` |
| 고정근무자와 혼재 | 근무그룹을 유형별로 분리 생성 |
| 보상휴가 운영 | 휴가 설정에서 보상휴가 유형 생성, 인사팀 수동 지급 |

### 한계사항
- 고정 연장시간(포괄임금 등) 자동 차감 기능 없음 → 연장 집계는 되나 고정분 제외 계산은 수동
- 정산기간 설정 후 변경 불가 → 초기 설정 신중히
- 탄력적 근로시간제 법적 요건(노사 서면합의)은 고객사가 별도 이행 필요
- 정산기간 중 퇴직자 연장시간 정산은 수동 확인 필요

## 유형 4. 간주근로제 / 재량근로제

### 판단 기준
- "임원", "간주근로", "출퇴근 기록 불필요"
- "사업장 밖 근무", "외근 위주", "근무시간 측정 어려움"
- "소정근로시간 근무한 것으로 인정"

### 세팅 방법

**근무 템플릿**
- 출퇴근 시각 형식상 입력 (실제 기록 없음)
- 하루 근무시간: 소정근로시간 입력

**근무그룹**
- 근무제 유형: `간주근무` (`validWorkCd === "PLAN"`, `KB:product/admin/work/group-setting.md` § "유효 근무 코드")
- 기본 근무시간 기준: `근무 계획으로 간주`
  - 출퇴근 버튼 없음 (`KB:product/user/home/checkin-widget.md` § Type 1: WorkReg "근무 계획 시간 사용 그룹"), 계획 시간 자동 집계
- 근무시간 표시 여부: `표시하지 않음` 설정 가능 (임원 등 근무시간 비노출 필요 시 — `workTimeVisibleCd === "DENIED"`, 특정 고객사 요청)
- 연장/야간: 일반적으로 `연장 가능` (별도 승인 불필요)

### 자주 나오는 케이스

| 케이스 | 세팅 포인트 |
|---|---|
| 임원 — 근무시간 관리 불필요 | 간주근무 + 근무시간 표시 OFF |
| 외근직 — 외근 신청 시 소정근로 자동 인정 | 기타근무 항목(외근) 사용 (`KB:product/user/applications/other-work.md` § 2) |
| 재택 병행 | 출근지 관리: 재택근무 허용 ON |

### 한계사항
- 실제 출퇴근 기록 없으므로 근무시간 소명 자료 없음
- 타임존 변경 기능 개발 중 (해외 근무자 적용 불가)
- 외부 시스템 연동 필요 시 talenx SC 별도 문의

## 유형 5. 교대근무제

### 판단 기준
- "3조3교대", "2조2교대", "주간/오후/야간" 등 교대 표현
- 조별 순환 근무, 계획근무표 운영
- 비번일, 주휴일 별도 지정

### 세팅 방법

**근무 템플릿** — 교대 시간대별로 각각 생성
- 예: `오전(08~17시)` → 출근 08:00, 소정근로 8시간, 휴게 11:00~12:00
- 예: `오후(14~23시)` → 출근 14:00, 소정근로 8시간, 휴게 18:00~19:00
- 예: `야간(23~08시)` → 출근 23:00, 소정근로 8시간, 휴게 03:00~04:00

**근무그룹**
- 근무제 유형: `스케줄근무`
- 기본 근무시간 기준: `출퇴근 기록` → 출퇴근 필수
- 야간근무 허용: `야간 가능` (`nightPmitCd === "P"`)
- 연장/휴일근무: 운영 정책에 따라 설정

**그룹 스케줄**
- 반복 설정: `휴일에도 반복일정 적용` (교대근무는 공휴일 무관하게 패턴 유지)
- 순환 패턴 설정 (예: 오전 5일 → 오후 5일 → 야간 5일 → 비번 → 주휴 반복)

### 실제 케이스 예시 — TXR CS팀 교대근무 지침

고객사가 아래와 같은 내용의 지침을 제공한 경우:
- 3조3교대: 오전 08~17시 / 오후 14~23시 / 야간 23~08시
- 비번/주휴일 근무 시 2조2교대로 전환: 오전 08~20시 / 야간 20~08시
- 휴게시간: 오전 11~12시 / 오후 18~19시 / 야간 03~04시
- 계획근무표 월 단위 작성, 매월 시작 10일 전 공유
- 연장/야간/휴일근로 정산은 연봉계약서 기준 (포괄임금)

**세팅 방향**:
- 근무그룹 유형: `스케줄근무`
- 근무 템플릿 5개 생성: 오전(08~17), 오후(14~23), 야간(23~08), 비번오전(08~20), 비번야간(20~08)
- 각 템플릿별 휴게시간 설정
- 그룹 스케줄: 순환 패턴 설정, `휴일에도 반복일정 적용`
- 연장/야간 허용: `연장 가능` (포괄임금이므로 수당 별도 산출 불필요)
- 근무시간 표시: 포괄임금 고객사의 경우 근무시간 표시 여부 고객사 정책 확인 필요

### 자주 나오는 케이스

| 케이스 | 세팅 포인트 |
|---|---|
| 공휴일에도 정상 근무 | 그룹 스케줄: `휴일에도 반복일정 적용` |
| 비번/주휴 근무 시 다른 시간대 적용 | 2조2교대용 템플릿 별도 생성, 해당일 수동 적용 |
| 야간 크로스 (전일 23시 출근~익일 08시 퇴근) | 야간 템플릿 익일 퇴근시각 설정 — 일자 귀속 처리 방식 확인 필요 |
| 계획근무표 월 단위 제출 | 그룹 스케줄 + 개인 스케줄 변경 신청 프로세스 안내 |

### 한계사항
- 비번/주휴일 임시 2조2교대 전환은 수동으로 개인 스케줄 수정 필요
- 야간 크로스 근무 일자 귀속 처리 방식 케이스별 확인 필요 → **BizOps 확인 필요**
- 조별 패턴이 개인마다 다른 경우 수동 관리 필요

# 2부. 휴가 세팅

## 휴가 세팅 구조 이해

근무 세팅과 마찬가지로 휴가 세팅도 2단계 구조. 근무그룹과 휴가그룹은 **독립적**으로 운영되며, 구성원은 두 그룹에 각각 별도로 배정된다 (`KB:product/admin/leave/group-setting.md` § B).

```
[1단계] 휴가 설정 (어드민 #12) — 회사 공통 설정
  - 연차 제도 (부여 기준, 1년 미만, 첫 회계연도, 근속연수별, 초과사용 등)  → § A-1
  - 연차 정산 기준 (의무 사용, 이월, 보상)                                 → § A-2
  - 연차 외 휴가 제도 (경조, 병가, 보상, 포상 등 유형별)                   → § A-3
                                                              KB:product/admin/leave/overview.md

[2단계] 휴가그룹 설정 (어드민 #13) — 같은 휴가제도 적용 구성원 단위
  - 연차 제도 1개 선택 + 연차 정산 기준 1개 선택
  - 연차 외 휴가 제도 복수 선택 (적용할 항목만 체크)
  - 구성원 배정
                                                              KB:product/admin/leave/group-setting.md § B
```

> ⚠️ **근무그룹과 휴가그룹은 별개** — 구성원을 근무그룹에 배정했더라도 휴가그룹에 별도로 배정해야 휴가 기능 사용 가능

### 연차 부여 기준별 세팅

**입사일 기준**
- 연차 부여 기준: `입사일 기준`
- 구성원별 입사일 기준으로 연차 자동 생성
- 주로 스타트업, 소규모 기업에서 사용

**회계연도 기준**
- 연차 부여 기준: `회계연도 기준`
- 회계연도 시작일은 어드민 #5에서 설정 (`KB:product/admin/work/base-setting.md` § 1)
- 매년 회계연도 시작일에 일괄 부여
- 중도입사자는 첫 회계연도 연차 일할/월할 계산 설정 필요
- 가장 일반적인 대기업/중견기업 방식

**연차 미부여 (임원·계약직 등)**
- 연차 부여 기준: `부여 안함`
- 연차 0개 생성, 1년 미만 연차도 미생성

### 휴가 신청 시간대 설정

| 운영 방식 | 설정 |
|---|---|
| 오전반차/오후반차/종일만 허용 | `고정` → 각 옵션별 시간대 입력 |
| 1시간 단위 자유 신청 | `자율` → 허용 단위 선택 |

| 유연근무제 — 출근 시간 다양해서 시간대 고정 불가 | `자율` 권장 |

## 연차 외 휴가 제도 세팅

### 세팅 구조
연차 외 휴가는 유형별로 개별 생성 후 휴가그룹에 매핑한다.

| 설정 항목 | 내용 |
|---|---|
| 휴가제도명 (어드민) | 내부 관리용 명칭 |
| 휴가제도명 (사용자) | 구성원 앱 화면에 표시되는 명칭 |
| 근무 인정 여부 | 해당 휴가 시간을 근무시간으로 인정할지 여부 |
| 유/무급 | 유급 처리 여부 |
| 부여 방식 | 주기 반복 / 수동 부여 / 신청에 따라 사용 (아래 상세 참조) |
| 휴일/휴무일 포함 여부 | 주말이 휴가 기간에 포함되는지 여부 |
| 성별 제한 | 특정 성별에만 적용 (보건휴가, 출산휴가 등) |
| 기간 제한 | 특정 기간 내에만 사용 가능한 경우 (여름휴가 등) |
| 휴가 사용 시간대 | 자율 / 고정 / 자율+고정 |
| 파일 첨부 / 코멘트 | 필수/선택 |

> 사용자/어드민 명칭 분리 운영: `KB:product/admin/leave/overview.md` § A-3 (연차 외 휴가 제도)

### 부여 방식별 사용처

| 부여 방식 | 설명 | 주요 사용 예 |
|---|---|---|
| 주기에 따라 반복 사용 | 매년/매월 자동으로 반복 제공 | 여름휴가, 여성 보건휴가 |
| 수동 부여 | 관리자가 직접 대상자에게 지급 | 포상휴가, 보상휴가, 근속휴가 |
| 신청에 따라 사용 | 구성원이 직접 신청 → 승인 후 사용 | 경조휴가, 병가, 공가 |

> **수동 부여**는 어드민 #14 "수동 휴가 지급" 화면에서 (`KB:product/admin/leave/non-annual-management.md` § C-2). 단위는 시간만 가능 (의도된 설계 — 소정근로시간이 회사/사람마다 달라 일 단위 모호).

### 자주 나오는 휴가 유형별 세팅 방향

| 휴가 유형 | 유/무급 | 부여 방식 | 주요 설정 포인트 |
|---|---|---|---|
| 경조휴가 | 유급 | 신청에 따라 사용 | 사유별 일수 다름 → 사유 유형 구분 or 코멘트 필수 |
| 병가 | 무급 (또는 유급) | 신청에 따라 사용 | 연 사용일수 제한 설정, 파일 첨부 필수 가능 |
| 보상휴가 | 유급 | 수동 부여 | 인사팀이 월 단위 일괄 지급, 사용 기한 설정 |
| 포상휴가 | 유급 | 수동 부여 | 특정 사유 발생 시 개별 지급 |
| 여름휴가 | 유급 | 주기에 따라 반복 | 기간 제한 설정 (예: 7/15~8/31 이내 사용) |
| 보건휴가 | 유급 | 주기에 따라 반복 | 성별 제한: 여성만, 매월 1일 |
| 출산휴가 / 육아휴직 | 유급/무급 | 신청에 따라 사용 | 법적 기준 확인 필요, 기간 제한 없음 |
| 공가 / 민방위 | 유급 | 신청에 따라 사용 | 파일 첨부 필수 |

| 외부 시스템(세콤 등) 연동 출퇴근 | `validWorkCd === "EXTERNAL"` (현재는 세콤만 지원, `KB:product/user/home/checkin-widget.md` § "데이터 모델"). 시스템별 연동 가능 여부 상이, SC 별도 협의 필요 |
| 포괄임금 + 교대근무 — 근무시간 표시 여부 | 고객사 정책 및 민감도에 따라 다름. `workTimeVisibleCd === "DENIED"` 활용 |
| 야간 크로스 근무 일자 귀속 처리 | 백엔드 `ValidWorkDayResolver` 자정 cutoff 룰 (`KB:product/user/home/checkin-widget.md` § "자정 이후 특수 동작") — 케이스별 확인 필요 |
| 탄력적 근로시간제 6개월 단위 | 법적 요건(노사합의) 및 시스템 지원 범위 확인 필요 |
| 해외 거점 타임존 적용 | 현재 서울 타임존 고정, 개발 예정. `WorkGrpVo.timeZoneId` 필드 존재 (`KB:product/admin/work/group-setting.md`) |
| 고정 연장시간 자동 제외 후 초과분만 연장 산정 | 현재 수동 처리 — 시스템 지원 범위 확인 필요 |
| 근무 데이터 외부 시스템(급여 등) 연동 | 연동 가능 여부 및 방식 SC 확인 필요 |

## 운영자가 반드시 확인할 cross-domain 영향

세팅 시 한 영역의 변경이 다른 영역에 미치는 영향을 사전 인지:

| 변경 | 영향 |
|---|---|
| 근무그룹 확정 | **그룹명/메모/근무시간 표시 여부 외 변경 불가** (`KB:product/admin/work/group-setting.md` § "확정 후 제약") |
| 정산기간 설정 | 한번 설정 후 변경 불가 (운영 시작 전 신중) |
| 휴일 추가/삭제 | 모든 근무그룹에 영향 (휴일 비활성화 시 confirm 모달, `KB:product/admin/work/base-setting.md` § 2) |
| 출근지 비활성화 | 모든 사용 그룹의 GPS 검증 후보에서 제외 |
| 기타근무 항목 삭제 | **모든 그룹 매핑 cascade 삭제** (다른 영역과 차별, `KB:product/admin/work/base-setting.md` § 5) |
| 근무 마감 (#9) | 마감일 모든 신청서 / 출퇴근 / 휴가 차단 (`KB:product/admin/work/close-work-data.md` cross-domain 13곳) |
| 어드민 출퇴근내역 직접 수정 | 사용자 변경 신청 시도 시 차단 (`hasModifiedWorkRecord`, `KB:product/admin/work/check-work-data.md`) |
| 휴가그룹에 매핑된 연차 제도 / 정산 기준 | 사용여부 변경 / 삭제 불가 (`KB:product/admin/leave/overview.md` § A-1, A-2) |
| 인사 ↔ 근무 모듈 연동 중 | 비활성→활성은 인사 발령으로만 (`KB:product/admin/etc/sync.md` § #1) |
