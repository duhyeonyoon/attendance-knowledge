**진입 경로**:
1. **당일 근무내역 변경** (U4, L155–166): 출퇴근 위젯에서 "근무 내역 변경" 버튼으로 진입
   - 트리거 조건: 출근 요청이 취소/반려되어 출근 기록 없는데 퇴근만 있는 경우 (`workHistoryChangeRequired`)
   - "근무 내역 변경이 필요합니다" 문구
   - 요청 시 "요청중" 상태 + 버튼 disabled
   - 승인 시 "퇴근" 상태 + 출근/퇴근 시간 노출 + 재신청 가능
2. **근무내역 변경 (일반)** (U7, L210–258): 내 근무 캘린더에서 과거 날짜 클릭 또는 출퇴근 위젯에서 근무 신청 → 근무내역 변경 선택

**열림 시 동작**:
- 이미 입력된 출근/퇴근 정보 있으면 입력된 상태로 모달 오픈
- **근무시간 표시 안함 + 출근인정시각 이전 출근**한 경우 → 첫 출근시간이 **출근인정시각으로 보정**되어 표시
- 출근인정시간 이전으로 출근시간 설정 시 → ~~"출근 인정시간 전 근무 미인정"~~ (요약) → 화면 원문 "출근인정 시각(HH:mm)부터 근무 시간으로 인정합니다." (2026-11-05)
- 근무 귀속일 하루 시간 벗어난 입력 → 요청 시 경고 모달:
  > "입력하신 출퇴근 시각은 익일 근무를 포함하고 있습니다." / "해당 시간은 선택한 날짜의 근무로 기록됩니다. 이대로 변경하시겠습니까?" (2026-11-05 원문)

**필수 입력 (2026-11-05 해소)** — `pp:src/components/workflow/shared/template_drawer/contents/RegEdit.tsx:992-1031`:
- 요청일 필수 ("요청일을 입력합니다."), 미래 날짜 불가 ("요청일은 현재 날짜 이전으로만 선택할 수 있습니다.")
- 출퇴근·자리비움 중 최소 1건 입력 ("통합 근무내역 변경 데이터를 입력합니다.")
- **출퇴근 행을 추가했다면 출근·퇴근 시각 모두 필수** — 한쪽이 "없음"이면 행 개수와 입력 쌍이 맞지 않아 "출퇴근, 자리비움 데이터 검증을 통과하지 못했습니다."로 요청 불가 (자리비움 행도 시작·종료 쌍 필수). 미입력 칸은 빨간색 "없음"으로 표시
- 출퇴근 행 개수 제한은 화면에 없음 (추가 버튼으로 여러 회차)
- 첨부/코멘트 필수는 신청서 설정(`requireFileYn`/`requireCommentYn`)
- [요청] 버튼 비활성: 마감일 / 그룹 사용 불가 / 어드민 수정 일자 / 같은 날 요청중 신청 존재

**같은 날 요청중 신청 차단 메시지**: "선택한 날짜에 이미 신청한 출근 요청이 있습니다." / "… 퇴근 요청이 있습니다." / "… 통합 근무내역 변경 요청이 있습니다." / "… 출퇴근 내역 변경 요청이 있습니다."

**밸리데이션 (5종)**:

1. **시간 역전**
   - 출근/퇴근 역전 → "퇴근시간이 출근시간 전입니다."
   - 출근 = 퇴근 → "출근시간과 퇴근시간이 동일합니다."
   - 두 번째 출근시간 < 첫 번째 퇴근시간 → "출근시간이 이전 퇴근시간 전입니다."

2. **자리비움**
   - 자리비움 시작/종료 역전 → "종료시간이 시작시간 전입니다."
   - 자리비움이 출퇴근 시간 외 → "자리비움 시간은 출퇴근 시간 이내로 작성해야합니다."
   - 자리비움 시작 = 종료 → "자리비움 시작시간과 종료시간이 동일합니다."

3. **초과근무제한시간 (최대)**
   - 변경 시간에 연장/야간 근무 포함 시 잔여시간 문구 표시
   - 잔여시간 초과 시 밸리데이션 ("`근무일, 주간` 기준 잔여 시간을 초과했습니다." 형식). 안내 "잔여시간은 통합 근무내역 변경 신청 전 근무시간을 기준으로 산정된 초과근무 가능 시간입니다."
   - 최대 근무시간 초과: "최대 근무시간을 Nh 초과했습니다."

4. **초과근무제한시간 (최소)** — 근무그룹 룰
   - **휴일**: 기본근무시간이 최소 미만 → 인정근무 제외 + 경고
   - **근무일/휴무일**: 연장근무시간이 최소 미만 → 인정근무 제외 + 경고
   - 경고 문구: "최소 연장근무시간(Nh)보다 작아 근무시간으로 인정되지 않습니다." (해당 시간 옆 "(미인정)")

5. **연장근무 정보**
   - 연장 휴게시간 포함 시 정보 표시
   - 고정 유형 연장휴게시간은 시간정보까지 확인 가능

**관리자 수정 후 사용자 측 차단**: 어드민이 출퇴근내역 직접 수정한 일자에 사용자가 변경 신청 시도 → ~~"관리자에 의해 수정된 내역이 있어 신청할 수 없습니다"~~ → **(2026-11-05 원문)** "해당 일자의 근무내역은 어드민이 수정 및 확정하였습니다." 경고 + [요청] 비활성 (`RegEdit.tsx:1201-1205`) (`KB:product/admin/work/check-work-data.md` § "사용자 관점 검증 시나리오" 참조)

**마감 차단**: 요청/승인 불가 — "선택한 일자의 근무가 마감되어 근무내역을 변경할 수 없습니다."

**휴일근무 '근무 불가' 그룹의 휴일 신청 (2026-11-05 추가)**: 근무그룹 휴일근무 허용이 "근무 불가"인데 신청일이 휴일이면 서버가 저장을 거절 — "휴일 근무내역 변경을 할 수 없도록 설정되어 있습니다. 담당자에게 문의바랍니다." (`be:service/appls/WorkRecordChangeApplsService.java:682-692`, optimiz-time `origin/dev` b534d01df). 출퇴근 내역 변경(1072)은 같은 상황에서 "휴일 출퇴근 내역 변경을 할 수 없도록 설정되어 있습니다. 담당자에게 문의바랍니다."

## 출퇴근 내역 변경(1072)과의 차이 (2026-11-05 추가)

| 둘 다 사용하는 그룹의 진입 기본값 (캘린더 과거 날짜·위젯 "근무 내역 변경" 버튼) | — | **출퇴근 내역 변경이 먼저 열림** (`pp:src/lib/attendance/workTimeRecordChangeRequest.ts:55-72`). 신청서 상단 유형 드롭다운으로 전환 가능 |
