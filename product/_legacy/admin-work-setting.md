# 근무설정 (어드민 #5) — 클라이언트 레벨 마스터

## 개요

**근무설정 = 클라이언트(고객사) 단위의 마스터 데이터**. 회계연도/한주시작 외에도 휴일/출근지/근무 템플릿/기타근무 항목을 여기서 정의하고, **근무그룹이 이 마스터를 상속하여 사용 여부만 토글**합니다.

근무그룹 deep-dive (`KB:product/admin-work-group.md` § "근무설정 탭 — 8개 섹션 구조")에서 휴일/출근지/기타근무 섹션의 항목들이 "클라이언트에서 상속"이라고 했는데, **그 클라이언트 정의 화면이 바로 이 영역**.

```
[어드민 #5 근무설정]                                    ← 마스터 정의 (클라이언트 단위)
   ├─ 시간 조회 (회계연도 + 한 주 시작)
   ├─ 휴일 목록 (법정 + 회사 휴일)
   ├─ 출근지 목록
   ├─ 근무 템플릿 (공통)
   └─ 기타근무 항목 (공통)
        ↓ (사용 여부 상속 — 근무그룹은 토글만 가능)
[어드민 #6 근무그룹 설정]                                ← 그룹별 정책 (사용 여부 토글)
        ↓
[사용자 ppfront]                                        ← 출퇴근/근무계획/스케줄에 반영
```

## § 1. 시간 조회 탭 (L184–195)

QA에서는 가장 짧은 섹션이지만 **연차 계산 등 광범위한 영향**.

### 회계연도 시작일

> 회계연도 시작일은 근무 기준 1년의 첫 날짜를 판단하는 일자로 **연차 생성의 근속 년 수 계산 등에 사용**된다.

- 조회만 가능 (변경 UI 명시 없음 — [TBD] 변경 가능 여부)
- 영향 범위:
  - 연차 자동생성 시 귀속연도 계산
  - 주기 반복 사용 휴가의 주기 시작일 (`KB:product/leave-domain.md`)
  - 근무 정산 사이클 계산

### 한 주의 시작 요일

> 한 주의 시작은 주 52시간을 계산하는 기준, 주 단위 제한 휴가의 기준 등에 사용된다. (개발필요)

- **회사별 별도 설정 가능** (`WeekStartSettingDialog.tsx`)
- **제약**: 이미 설정된 회사 또는 **근무 집계가 있는 회사**는 변경 불가
  - 이유 추정: 주 52시간 계산 기준이 바뀌면 과거 집계 무효화 위험
- "(개발필요)" 표시 — 일부 기능 미완성 가능성

### 백엔드 API

`be:controller/setting/ClientWorkSettingController.java`:

| Method | Path | 용도 |
|--------|------|------|
| GET | `/time/options/sc` | 클라이언트 근무설정 옵션 조회 |
| GET | `/time/company-time-option` | 회사별 근무설정 옵션 (한 주 시작 요일) 조회 |

> POST 동작이 "ID가 있더라도 새 UUID를 부여하여 새로 생성한다"는 점 흥미로움 — 회사별 옵션은 변경 불가 + 새로 만드는 방식 (이력 보존?) [TBD]

### 관련 DB 테이블

## § 2. 휴일 설정 탭 (L197–228)

휴일은 **3가지 유형**이 한 화면에 모임:

| 유형 | 정의 위치 | 영향 범위 |
|------|------|------|
| **법정 공휴일** | HCG가 관리, 클라이언트 동기화 | 클라이언트 전체 |
| **회사 휴일 (공통)** | 이 화면에서 추가 | 클라이언트 전체 (모든 근무그룹) |
| **근무그룹 휴일** | 근무그룹에서 추가 | 해당 근무그룹만 |

> 💡 영향 범위 (QA L199–201):
> - 법정/회사 휴일 → **근무그룹 관계 없이 클라이언트 전체** 영향
> - 근무그룹 휴일 → **해당 근무그룹 내**만 영향
> - 영향받는 화면: 어드민 근무그룹-휴일관리/그룹스케줄, 사용자 내근무/구성원근무/근무스케줄

### 법정 공휴일 동기화

- HCG가 관리하는 법정공휴일을 갱신 (`:arrows_counterclockwise:` 동기화 버튼)
- **제약**: **당해부터 미래만** 가능. 과거년도 동기화 불가
  - 메시지: "이전 년도의 법정공휴일은 불러올 수 없습니다."
- 회사별로 사용 원치 않으면 비활성화 가능

### 회사 휴일 추가/삭제

- [휴일추가] 모달로 추가
- 추가된 공통 휴일 → **근무그룹의 근무설정 > 휴일관리에도 자동 공유**
- 각 근무그룹에서 사용 여부 토글 가능 (그룹 단위 비활성화)

**삭제 룰** (L208):
- **미래 날짜** 휴일 → 삭제 가능
- **과거/오늘 포함** 휴일 → 삭제 불가 (집계 데이터 보호)

### 근무그룹 휴일 (이 화면에서)

- **이 화면에서 제어 불가** — 어떤 근무그룹에 어떤 휴일이 있는지 **확인만** 가능
- 리스트의 `info` 아이콘에 마우스 오버 시 → 어느 근무그룹에서 만든 휴일인지 표시

### 화면 구성: 리스트 / 캘린더

**리스트 모드** (기본):
- 현재 년도 휴일정보 (페이지당 100건, 화살표로 년 이동)
- 사용중/사용안함 필터
- 날짜 오름차순
- 로우 클릭 → 휴일 수정 모달
- 사용여부 비활성화 시 → **Confirm 모달** ("해당 휴일을 사용하는 모든 근무그룹에 영향이 갈 수 있다")
- **법정 휴일 수정 제약**: 사용여부 / 유무급 / 메모만 수정 가능 (날짜/이름 등 불가)

**캘린더 모드**:
- 월 별 캘린더
- 휴일 적용 범위에 따라 **색상 구분** (법정공휴일/회사/근무그룹)
- 같은 일자 중복 시 가나다 순 정렬
- 타이틀 클릭 → 휴일 수정 모달

### 백엔드 API

| Method | Path | 용도 |
|--------|------|------|
| GET | `/time/holi-calens` | 휴일 달력 조회 (조회조건 기반) |
| POST | `/time/holi-calens/sync` | 전역 휴일 달력으로 동기화 (법정공휴일 갱신) |
| POST | `/time/holi-calen` | 휴일 생성 (회사 휴일 추가) |
| PUT | `/time/holi-calens/{holiCalenId}` | 휴일 수정 |
| DELETE | `/time/holi-calens/{holiCalenId}` | 휴일 삭제 |

### 관련 DB 테이블

- `TM_HOLI_CALEN` — 휴일 달력 (3유형 모두 저장, 구분 컬럼으로)
- `TM_WORK_GRP_HOLI_CALEN` — 근무그룹-휴일 매핑

## § 3. 출근지 설정 탭 (L230–254)

### 출근지 유형 2종

| 유형 | 정의 위치 | 영향 범위 |
|------|------|------|
| **공통 출근지** | 이 화면에서 추가 | 클라이언트 전체 (근무그룹이 사용 여부 토글) |
| **근무그룹 출근지** | 근무그룹에서 추가 | 해당 근무그룹만 (이 화면에서 확인만, 수정 불가) |

### 화면 구성

- 출근지 리스트 (페이지당 100건)
- 사용중/사용안함 필터
- [출근지 추가] → 모달 오픈
- 공통 출근지 클릭 → 수정 모달 (수정/삭제 가능)
- **근무그룹 출근지 클릭** → 상세 조회만 (수정/삭제 불가, `info` 아이콘으로 출처 그룹 확인)

### 사용여부 비활성화 영향

- 비활성화 시 Confirm 모달: "해당 출근지를 사용하는 모든 근무그룹에 영향이 갈 수 있다"
- 비활성 시 근무그룹-근무설정-출근지관리 리스트에서 **노출 안 됨**

### 출근지 상세 설정 (모달)

- 추가: 바로 입력 모달
- 수정: 최초 조회 → [수정] 버튼으로 입력 활성화
- 수정/삭제는 **공통 유형만** 활성화

**입력 항목**:
- 출근지명, 메모
- **출근지 주소**: 키워드 기반 위치 제안 → 선택 시 좌표 자동 세팅
  - 주소 삭제 → 좌표 초기화
- **좌표 + 반경**: 지도에 핀 + 반경 범위 표시
- 정보: IP/WiFi 등 (모달 입력)

### 백엔드 API

| Method | Path | 용도 |
|--------|------|------|
| GET | `/time/work-plcs` | 출근지 리스트 조회 |
| POST | `/time/work-plc` | 출근지 생성 (담당자 권한) |
| PUT | `/time/work-plcs/{workPlcId}` | 수정 |
| DELETE | `/time/work-plcs/{workPlcId}` | 삭제 |

> 권한 = `(담당자 권한)` 명시 — 어드민이 아닌 담당자(서브 어드민) 권한으로도 수정 가능

### 관련 DB 테이블

- `TM_WORK_PLC` — 출근지 마스터
- `TM_WORK_PLC_IP` — 출근지 IP 매핑
- `TM_WORK_PLC_WIFI` — 출근지 WiFi 매핑
- `TM_WORK_GRP_WORK_PLC` — 근무그룹-출근지 매핑

> 출근지 검증 로직은 사용자 출퇴근 위젯의 GPS 검증과 직결 (`KB:product/user-checkin-widget.md` § "GPS 검증")

## § 4. 근무 템플릿 탭 (L256–289)

> **용어 정리**: **근무 템플릿 = 근무 계획(=근무 스케줄)의 종류**. 클라이언트 레벨에서 "어떤 종류의 근무 계획이 가능한지" 정의하는 마스터 데이터. 그룹은 이 마스터를 상속해서 어떤 템플릿을 사용할지 선택, 사용자는 캘린더에서 이 템플릿이 적용된 근무 계획(스케줄)을 봄.

### 근무 템플릿 유형

| 유형 | 정의 위치 | 영향 범위 |
|------|------|------|
| **공통 템플릿** | 이 화면에서 추가 | 모든 근무그룹의 "템플릿 추가" 모달에서 선택 가능 |
| **근무그룹 템플릿** | 근무그룹에서 추가 또는 공통 수정 시 자동 생성 | 해당 근무그룹만 (이 화면에서 확인만) |

> 근무그룹 deep-dive에서 본 룰: "템플릿 구분이 '공통'인 경우 **수정 시 '근무그룹' 구분으로 신규 저장**" → 원본 보존 + 그룹 fork

### 신규 템플릿 디폴트 값 (L262–268)

```
근무구분        : 근무일
출근시간        : 정해진 시각에 출근합니다
퇴근시간        : 하루 근무시간이 지나면 퇴근합니다
하루근무시간     : 8 (소정근로시간)
휴게시간        : 근무시간에 따라 자동 적용
연장휴게시간     : 근무시간에 따라 자동 적용
```

### 사용여부 활성/비활성

- 활성 → 근무그룹 템플릿 설정 - 전체 템플릿에서 추가 가능
- 비활성 → 전체 템플릿에서 노출 안 됨 (= 추가 불가)

### 근무 템플릿 상세 설정 (별도 페이지)

페이지: `/attendance/work/base_setting/work_template`

**근무구분 분기**:
- **근무일** → 모든 속성 입력 가능
- **휴일/휴무** → 템플릿명/색상만 입력 가능 (나머지 속성 숨김 처리)

**출근시간 분기**:
- **자유롭게 출근** → **코어타임 설정 가능**
- **정해진 시각** → **고정출근시간** 필수 (미입력 시 저장 불가)

**휴게시간 / 연장휴게시간**:
- **고정** 설정 시 → 하나 이상의 휴게시간 범위 필수

- 사용여부 활성 → 근무그룹 설정 > 기타근무 항목 리스트에 노출

페이지: `/attendance/work/base_setting/etc_work` (상세), `/attendance/work/base_setting/etc_work/create` (생성)

**상세 페이지 동작**:
- 추가: 바로 입력
- 수정: 최초 조회 → [수정]로 입력 활성화 → [저장]/[취소]
- 삭제: 조회 상태에서 [삭제] 버튼

### 백엔드 API

| Method | Path | 용도 |
|--------|------|------|
| GET | `/time/other-works` | 기타근무 리스트 조회 |
| GET | `/time/other-works/{otherWorkId}` | 상세 조회 |
| POST | `/time/other-work` | 생성 |
| PUT | `/time/other-works/{otherWorkId}` | 수정 |

## 근무그룹과의 상속 관계 ⭐

이 영역의 가장 중요한 부분. **클라이언트 → 그룹 상속 메커니즘**.

### 상속 패턴 4가지 (각 영역별 차이)

| 영역 | 클라이언트 정의 | 그룹 사용 | 비활성화 영향 |
|------|------|------|------|
| **휴일** (법정/회사) | 마스터 휴일 추가 | 그룹은 **사용여부 토글만** | 그룹 휴일관리 리스트에서 제외 + 사용자 캘린더 영향 |
| **출근지** (공통) | 마스터 출근지 추가 | 그룹은 **사용여부 토글만** | 그룹 출근지관리 리스트에서 제외 |
| **근무 템플릿** (공통) | 마스터 템플릿 추가 | 그룹이 **전체 템플릿에서 선택해 추가** + 그룹 fork 가능 (수정 시 새 row) | 비활성 = 그룹 전체 템플릿에서 미노출 |
| **기타근무 항목** (공통) | 마스터 항목 추가 | 그룹은 **사용여부 토글만** | 비활성 = 그룹 리스트에서 미노출. **삭제 시 cascade로 그룹 매핑도 삭제** |

### 그룹이 생성한 항목 (역방향)

근무그룹에서 만든 휴일/출근지/근무템플릿은 이 화면에 **조회만 가능** 형태로 노출됨:
- 휴일: 어느 그룹에서 만들었는지 `info` 아이콘 (수정/삭제 불가)
- 출근지: 어느 그룹에서 만들었는지 `info` 아이콘 (수정/삭제 불가, 상세 조회만)
- 근무 템플릿: 어느 그룹에서 만들었는지 `info` 아이콘 (수정 불가, 상세 조회만)

> ⚠️ **기타근무 항목은 그룹에서 신규 생성 불가** — 항상 클라이언트에서만 정의. 그룹은 사용 여부만 토글.

### 사용여부 비활성화 시 Confirm 모달

휴일/출근지 수정 모달에서 사용여부를 비활성화로 변경 시:
> "해당 휴일/출근지를 사용하는 모든 근무그룹에 영향이 갈 수 있다"

→ 잠재적 부작용 인지를 위한 강제 확인

### 임시 동작 / 차이점

- **휴일 삭제 룰**: 미래만 가능, 과거/오늘은 불가 (집계 데이터 보호)
- **기타근무 삭제 cascade**: 다른 영역과 달리 사용여부 비활성 외에 **삭제 시 그룹 매핑도 함께 삭제**
- **근무템플릿 fork**: 공통 템플릿을 그룹에서 수정 시 새 row로 분리 (원본 보존)
- **회사별 한 주 시작 변경 제약**: 이미 설정 / 집계 있으면 불가

이 영역 변경이 다른 영역에 미치는 영향:

| 근무설정 동작 | 영향 받는 영역 |
|------|------|
| 회계연도 변경 | 연차 자동생성 / 휴가 주기 시작일 / 근무 정산 사이클 |
| 한 주 시작 변경 | 주 52시간 계산 / 주단위 휴가 검증 |

| 회사 휴일 추가/비활성 | 근무그룹 휴일관리에 자동 공유 + 사용자 캘린더 |
| 출근지 비활성 | 사용자 출퇴근 위젯 GPS 검증 후보에서 제외 (`KB:product/user-checkin-widget.md`) |

| 기타근무 항목 비활성 | 그룹 기타근무 항목 리스트에서 미노출 + 사용자 신청서 옵션에서 제거 |
| 기타근무 항목 삭제 | **모든 그룹 매핑 cascade 삭제** (운영 주의) |

## 비즈니스 룰

1. **근무설정 = 클라이언트 마스터, 근무그룹 = 사용여부 토글** (4가지 영역 모두)
2. **휴일은 3유형** (법정 / 회사 / 그룹) — 영향 범위 다름
3. **법정 공휴일 동기화는 미래만** — 과거년도 불러올 수 없음
4. **휴일 삭제는 미래만** — 과거/오늘 포함 시 불가
5. **회사별 한 주 시작 변경 불가 조건** — 이미 설정 OR 집계 있음
6. **회사별 옵션은 변경이 아닌 새 row 생성** (POST `/company-time-option` 동작)
7. **공통 출근지 수정 가능, 그룹 출근지 조회만**
8. **근무 템플릿 공통 → 그룹 fork**: 수정 시 새 row로 분리 (원본 보존)
9. **기타근무 항목 삭제 cascade**: 다른 영역과 차별화 (사용여부 비활성 vs 삭제)
10. **그룹에서 만들 수 없는 영역**: 기타근무 항목 (휴일/출근지/근무템플릿은 그룹에서도 생성 가능)
11. **사용여부 비활성 시 Confirm 모달** — 잠재적 부작용 인지 강제
