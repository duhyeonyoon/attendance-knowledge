# 시스템 진입 (어드민 #1 + #2 + #3 + #4)

## 개요

근무 모듈의 **시스템 진입점** 4개 영역 통합:

| 영역 | 화면 | 역할 |
|------|------|------|
| **#1** | 연동 (인사/시스템 모듈) | 인사 ↔ 근무 모듈 데이터 동기화 |
| **#2** | 모듈 설정 (구성원/조직/직책) | 인사 데이터의 근무 모듈 표시 + 연차기산일 관리 |
| **#3** | 총괄 권한 | 어드민 도메인 접근 권한의 최상위 |
| **#4** | 권한 (직책자/서브어드민) | 운영 권한 위임 (직책자/담당자) |

이 4개 영역이 합쳐서 **"누가 무엇을 할 수 있는가"** 를 결정. 모든 다른 영역의 운영 전제.

## § #1. 연동 (L1–32)

### 인사 모듈 ↔ 근무 모듈 (L3–15)

**참고**: 근무관리 > 구성원 정보에서 근무모듈 구성원 데이터 확인 가능

#### 전체 연동 설정 (인사 데이터 연동 설정 > 근무관리)

| 동작 | 효과 |
|------|------|
| **연동 → 연동 안함** 변경 | 근무모듈의 구성원과 연동 해제 |
| **연동 안함 → 연동** 변경 | '연동 구성원'이 근무모듈 구성원과 연동 |
| **재연동 버튼** 클릭 | 수동으로 근무모듈 연동 이벤트 발생 |

#### 실시간 연동 (연동 중일 때)

**인사모듈 인사발령 확정 시**:
- 발령 내용이 근무모듈에 즉시 반영
- **휴직/퇴직** → 근무모듈 비활성
- **입사발령** → 근무모듈 구성원 추가

### 시스템 모듈 (시스템 > 계정관리) (L17–32)

사용자 계정 상태 변경의 근무모듈 영향:

| 변경 | 인사 ↔ 근무 연동 중 | 연동 X |
|------|------|------|
| **활성 → 비활성** | 근무모듈 비활성 + 모듈별 상태 비활성 | 동일 |
| **비활성 → 활성** | **근무모듈 활성 상태 변경 안 됨** (인사 발령으로만 활성화) | 근무모듈 활성 + 모듈별 상태 활성 |

> ⚠️ 중요한 비대칭: 비활성→활성 시 연동 중이면 **인사 발령이 우선**. 근무 모듈에서 임의로 활성 불가.

### 백엔드

- `be:controller/syncmember/SyncMemberByApiController.java` — API 기반 구성원 동기화
- `be:controller/externalrecord/SyncSecomRecordController.java` — **세콤 출퇴근 기록 동기화** (`validWorkCd === "EXTERNAL"` 그룹용, `KB:product/admin-work-group.md`)

## § #2. 모듈 설정 (L34–71)

### #2-1. 구성원 정보 (L36–44)

- **필터링 + 엑셀 다운로드**
  - [필터 재설정] → 필터 초기화 (재조회 X)
  - 엑셀 다운로드 → 사유 입력 모달 (다른 영역과 일관)
- **인사 모듈 연동 시** → 페이지 상단에 연동 정보 노출
- **연차기산일 수정/삭제 가능**:
  - 수정 시 [변경 내용 취소] / [저장] 버튼 활성화
  - [변경 내용 취소] → 수정 내용 되돌림

### #2-2. 조직 설정 (L46–50) — Read Only

- **인사 모듈과 연동된 조직 정보** 노출
- 조직 엑셀 다운로드 가능
- 조직 상세 조회 (관리자/구성원, **퇴직자 미조회**)

> 조직은 인사 모듈에서만 정의. 근무 모듈에서는 readonly.

### #2-3. 직책 설정 (L52–71)

#### 인사 연동 모드

- 인사 모듈 연동 시 → 페이지 상단 연동 정보 + **readonly 조회만 가능**

#### 직책 리스트 표시 룰

| 모드 | 노출되는 직책 |
|------|------|
| **근무 단독 모듈** | 클라이언트의 모든 직책 |
| **인사 + 근무 연동 중** | **인사 발령이 있는 직책만** + 인사 연동 이전 근무에서 추가한 직책 |
| 공통 | 퇴직자는 미조회 |

> 인사에서 새 직책 추가 → 인사 발령 없으면 근무 모듈에 미연동

#### 직책 세부 조회

- 동일 직책을 여러 조직에 본발령 + 겸 소속 시 → **툴팁으로 표시**

#### 근무 자체 관리 모드 (인사 연동 X)

직책 수정/삭제/생성 가능:
- 신규 직책은 상단에 생성
- 직책명: **중복 불가, 최대 20자**
- **구성원 있는 직책은 삭제 불가**
- 직책간 보기 순서 변경 가능

## § #3. 총괄 권한 (L73–77) — 매우 짧음

가장 짧은 영역 (3줄):

- **관리자 총괄 등록** → 어드민 도메인 접근 가능
- **모듈 총괄 권한자**:
  - 해당 모듈의 어드민 도메인 API 실행 권한
  - 전체 대상자 데이터 조회 가능
- **총괄 아닌 자가 어드민 도메인 API 호출 시** → **403 Access Denied**

> "총괄"이라는 용어 = 시스템 최상위 권한. 모듈별로 별개 (예: 근무관리 총괄, 휴가관리 총괄 등).

## § #4. 권한 (L79–180) — 가장 큼

**2가지 권한 종류**:
- **직책자 권한** (Manager) — 직책 기반 자동 부여 권한
- **서브어드민 권한** (Custom) — 명시적 지정 권한 (담당자 + 권한 범위)

### #4-1. 직책자 권한 (L81–101)

#### 메인 페이지

- 직책그룹 리스트
- 직책그룹명 아래에 포함된 **직책 표시**
  - 일립시스(`...`) 처리 시 **마우스 오버 → 툴팁**
- **인원수** 표시
- **X 아이콘** → 그룹 삭제
- 클릭 → 상세 페이지
- **미부여 직책** 클릭 → 직책그룹 추가 모달 (선택한 직책 자동 선택)

#### 상세 페이지

- **권한 설정 섹션** = [수정] 버튼 클릭 후 수정
- **포함 직책 / 조직장 조건 변경** → 직책자 현황 자동 업데이트
- **포함 직책 정렬** = 선택 순서 X, 기본 정렬 순서 (칩 정렬)
- 수정 중 [취소] → 초기값 복원
- **미부여 직책 추가 + 저장** → 미부여 직책에서 제거
- **직책자 현황 필터링** (이름 인풋: 엔터 또는 돋보기)

### #4-2. 서브어드민 권한 (L103–180) — 가장 복잡

**구조**: 권한그룹 (단위) → 담당자 (사람) → 권한 범위 (대상)

#### 메인 페이지

- 컬럼: 서브어드민 그룹명 / 담당자 / 회사
- 목록 없으면: "권한그룹을 생성합니다." 안내
- [권한그룹 추가]:
  - dialog → 그룹명 + 그룹 설명 입력 → 추가
  - 추가 완료 시 dialog 닫힘 + 목록 갱신
- **필터**: 그룹 모듈 / 담당자
- 클릭 → 상세 페이지

#### 상세 페이지 — 3개 카드 + 네비게이션

```
┌─────────────────────────────────┐  ┌──────┐
│ 1. 담당자 설정 카드              │  │ 네비 │
├─────────────────────────────────┤  └──────┘
│ 2. 권한 설정 카드                │
├─────────────────────────────────┤
│ 3. 기본 설정 카드                │
└─────────────────────────────────┘
```

**← 버튼 (뒤로 가기)**:
- 변경 사항 있음 → "알림" 컨펌 → 메인 이동
- 변경 사항 없음 → 즉시 메인 이동

**[권한그룹 삭제]**:
- 담당자 없음 → 활성 (삭제 가능)
- **담당자 있음 → 비활성** (삭제 불가)

#### 카드 1: 기본 설정

- [수정] 버튼 → 권한 그룹명 / 상세 설명 변경

#### 카드 2: 담당자 설정

**담당자 현황 목록**:
- 담당자 없음 → "담당자를 추가합니다." 문구
- **권한 종료일이 지난 담당자** → **투명도 0.3** (흐리게)
- 삭제 컬럼 외 영역 클릭 → **담당자 설정 페이지** 이동
- 삭제 컬럼 X 버튼 → "삭제" 컨펌 → 삭제
- [담당자 추가] → "담당자 추가" dialog
- "담당구성원" 필드: 권한범위 지정 후 범위내 구성원이 생기면 "??? 등 ?명" 표시

**담당자 추가 dialog**:
- **활성 상태 구성원만** 추가 가능
- 구성원 선택 + 권한 기간 "시작일" 입력 시 추가
- 완료 후 → **담당자 설정 페이지로 이동**

#### 담당자 설정 페이지 (가장 복잡)

**진입 시 상태**:
- 추가 모드: 이미 등록한 담당자 이름 + 권한 기간 입력 상태
- 수정 모드: 우측 상단에 **삭제, 취소, 저장** 버튼
- 추가 모드: 우측 상단에 **취소, 저장** 버튼

**페이지 이탈** (← 또는 [취소] 버튼):
- 변경 없음 → 즉시 상세 페이지 이동
- 변경 있음 → "알림" 컨펌 → 확인 시 이동

**저장 시 밸리데이션**:
- 담당 범위 또는 구성원 미추가 → 밸리데이션
- 권한 기간 시작일 삭제 → 밸리데이션

**담당 범위 (조직 다중 선택)**:
- 담당 범위 선택 → "범위내 구성원"에 자동 노출
- **조직은 다중 선택 가능** (단, 임시 제약 있음, 아래 참조)
- [+] 버튼으로 셀렉트 박스 추가, 2개 이상 시 우측 삭제 아이콘

**📌 임시 제약 (2025년 7월 8일 기준)**:
> 다중조직 선택 제한적 동작:
> - **단일회사 클라이언트**: 다중조직 선택 가능
> - **다중회사 클라이언트**: **회사 단위 전체조직만** 선택 가능 (다른 회사 조직 선택 차단)
> - 근무에서 회사-조직 관계 관리 추가 시 해제 예정

> ⚠️ 주석으로 가려진 옵션: "조직과 근무그룹은 다중 선택 가능 (근무그룹 지금 가려놓음)"

**범위내 구성원 (3가지 카테고리)**:

```
[담당 구성원] 탭                    [추가 구성원] 탭                [제외 구성원] 탭
   - 범위 선택으로 들어온 자          - 명시적으로 추가한 자          - 명시적으로 제외한 자
   - 추가 구성원도 표시됨            - 추가/삭제 가능                - 복구 가능
```

**구성원 추가 동작**:
- 추가하면 **"담당 구성원" + "추가 구성원"** 양쪽 등록
- **비활성 구성원도 조회됨** (담당 범위 내)
- 구성원 추가 dialog에서 **이미 추가된 구성원** → disabled + 툴팁 "이미 선택한 구성원입니다."

**제외 동작**:
- 담당 구성원 (추가 구성원 아닌 자) 체크박스 → [제외] 버튼 활성화
- 제외 → 담당 구성원에서 삭제 + 제외 구성원에 추가

**복구 동작** (제외 구성원 탭):
- 체크 + [복구] 버튼 또는 + 버튼 → 제외 구성원 복구
- **복구 시 분기**:
  - 담당 범위에 존재하면 → 담당 구성원에 다시 포함
  - 담당 범위에 없으면 → **삭제** (단순 제거)

**추가 구성원 삭제** (추가 구성원 탭):
- 체크 + [삭제] 또는 X 버튼 → "구성원 삭제" 컨펌 → 삭제
- 담당 구성원 탭에서도 사라짐

#### 카드 3: 권한 설정

**근무관리 업무권한 4종**:
- 근무 설정
- 근무 실무
- 휴가 설정
- 휴가 실무

**동작**:
- [수정] 버튼 → 편집 가능
- 구분 컬럼 좌측 체크박스 → **하위 상세분류 일괄 체크**
- 권한 체크박스 선택 + [저장]

## ⭐ 권한 모델 종합

### 4단계 권한 계층

```
[총괄 (#3)]                                 ← 어드민 도메인 접근 (모듈별 1명+)
   ↓
[직책자 권한 (#4-1)]                        ← 직책 기반 자동 부여 (그룹 단위)
   ↓
[서브어드민 권한 (#4-2)]                    ← 명시 지정 (담당자 + 범위)
   ↓
[일반 구성원]                               ← 본인 데이터만
```

### 권한 결정 흐름

1. **총괄인가?** → 어드민 전체 접근
2. **직책자인가?** → 직책그룹의 권한 (자동)
3. **서브어드민인가?** → 권한그룹의 담당자로 등록 + 권한 범위 + 권한 종류
4. **일반 구성원** → 본인 + (참여 워크플로우 기반)

### 사용자 화면 권한 분기 (이전 deep-dive와 연결)

- **U9 구성원 근무 / U10 구성원 휴가**: 직책자 권한이 있어야 타인 조회 (`KB:product/user-member-view.md`)
- **U11 근무스케줄**: 수정 권한이 있어야 역할 기준 탭 + 수정 페이지 (`KB:product/user-work-schedule.md`)
- **모든 어드민 화면**: 총괄 + 모듈 권한 필요

| 동작 | 영향 |
|------|------|
| 인사 발령 확정 | 근무 모듈 구성원 즉시 추가/비활성 |

| 권한 종료일 도래 | 자동으로 흐리게 (운영 알림) |
| 다중회사 클라이언트 다중조직 선택 시도 | 회사 단위 전체조직만 가능 (제약) |

## 비즈니스 룰

1. **인사 발령 우선**: 비활성→활성 시 인사 발령으로만 활성화 (연동 중)
2. **인사 연동 시 readonly**: 직책/조직 관리 불가
3. **인사 발령 없는 직책 = 근무 미연동**
4. **직책명 중복 불가, 20자 제한** (근무 자체 관리)
5. **구성원 있는 직책 삭제 불가**
6. **퇴직자 미조회** (조직/직책 모두)
7. **총괄 아니면 어드민 API → 403**
8. **권한그룹 삭제**: 담당자 없을 때만
9. **활성 상태 구성원만 담당자 추가 가능**
10. **다중회사 클라이언트 다중조직 제약** (2025.07.08 임시)
11. **권한 종료일 지난 담당자 → 투명도 0.3** (운영 가시화)
12. **추가 구성원 = 담당 구성원 + 추가 구성원 양쪽 표시** (이중 분류)
13. **제외 구성원 복구 시 범위 체크** (범위 외면 단순 삭제)
