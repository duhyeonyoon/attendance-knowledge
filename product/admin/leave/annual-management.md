### 연차 자동 생성 (`ad-qa:L979–987`)

다이얼로그 "연차 자동 생성" (`ManualAnlCreationDialog.tsx`):
- **연도 선택**(필수): 작년 / 올해 / 내년, 기본값 = 올해. (특정 고객사 커스텀은 2021년부터 선택 가능 — 임시 처리 TODO)
- 안내: "선택한 연도에 귀속되는 연차를 휴가그룹 설정에 따라 새롭게 생성합니다. 선택한 연도가 입사년도인 경우, 1년 미만 연차 전체가 생성됩니다. (퇴직자는 제외됩니다)"
- [확인] → 현황 조회(`anl-leaves/init/current-status/search`) 후 분기:
  1. 대상 중 **마감(정산 완료)된 구성원**이 있으면 → "연차 자동 생성 불가" + "선택한 구성원 중 연차가 마감되어 생성할 수 없는 구성원이 있습니다." / "연차를 마감하지 않은 구성원만 선택하여 조정하거나, 연차 정산을 취소한 후 연차 자동 생성을 진행합니다." → 중단
  2. 기생성자 없음 → "연차 생성" 확인: "선택한 구성원들의 연차를 생성하시겠습니까?"
  3. 기생성자 포함 → "이미 생성된 연차가 있는 경우, 현재 기준으로 새로 생성합니다. 이미 사용한 연차 이력은 유지되며, 새로 생성한 연차가 사용한 연차보다 적은 경우 초과 사용으로 표시됩니다." + "계속 하시겠습니까?" + "이미 생성된 연차가 있는 구성원 N" 목록(부여 n일 | 사용 n일)
- 생성 결과:
  - 전원 성공 → 스낵바 "연차 자동 생성을 완료하였습니다." + [부여 내역] 빨간 점
  - 일부 제외 → "연차 부분 생성 완료" + "아래 대상자는 변경된 사용기간을 벗어난 사용 내역이 있어 연차를 생성할 수 없습니다. 사용 내역을 조정한 후 다시 생성하시기 바랍니다." + "생성 불가 인원" 표(사용기간을 벗어난 사용일 / 변경된 사용기간)
  - 전원 제외 → "연차 자동 생성 불가" + "선택한 대상자 모두 변경된 사용기간을 벗어난 사용 내역이 있어 …"
- 생성 실패 1순위 원인: 생성 기준일에 휴가그룹 소속 없음 → 전체 실패(all-or-nothing). 권장 순서 = 연차기산일 입력 → 근무그룹 배정 → 휴가그룹 배정 → 자동 생성 (`_learnings/2026-07-29-annual-leave-concept-map.md`, Slack 실무 룰)
- 전 귀속연도 정산 결과 이월분이 있으면 자동 생성 시 부여 컬럼에 표시
- **근무율 미반영**: 출근율 80%/월 만근 조건은 아직 계산하지 않고 부여함 (`be:service/leavecreation/LeaveCreationService.java:88` TODO)

**행 컬럼**: 사번 / 지급 대상 / 연차유형 / 입사일 / 연차기산일 / 귀속연도 / 사용 시작일 / 사용 종료일 / 조정일(지급·차감 + 값) / 변경 전 · 변경 후

**1년 미만 연차의 사용 시작일 입력 가능** — 밸리데이션:
- 입사일 · 연차기산일 · 귀속연도 1월 1일보다 이전 불가
- 사용 종료일과 같거나 이후 불가

### 연차 정산 (`ad-qa:L1015–1029`)

[연차 정산 ▾] → 정산 / 정산 취소 선택:

**정산 처리**:
- 휴가그룹의 연차 정산 기준 설정에 따라 처리
- **귀속연도 단위**, 1년 미만 연차는 **합산 처리**
- 동일 귀속연도의 1년 미만 / 연차는 **각각** 정산/취소 가능
- 정산 결과가 컬럼에 표시, 잔여 컬럼 초기화
- 초과 사용분: 정상연차는 정산 기준의 "연차 초과 사용분 정산 정책"(전체 보상/이월/소멸)을 따름. 1년 미만 연차의 부족분(총사용 − 총부여)은 **1년 미만 연차(월차) 정책과 같은 방식**으로 청산 — 전체 보상이면 보상에서 차감(음수 가능), 전체 이월이면 차년도 부여에서 차감, 전체 소멸이면 청산 안 함 (2026-09-17 `hcgtheplus/optimiz-time#1642` §3)

**정산 취소 처리**:
- 다음 귀속연도 연차가 정산된 경우 → 취소 불가
- 다음 귀속연도 잔여가 이월분보다 적으면 → 회수 불가 (에러)
- 다음 귀속연도 잔여가 충분 또는 이월분이 마이너스 → 회수됨
- 회수된 이월분은 정산취소 연도의 잔여로 반환
- **(2026-11-05 Slack 확인)** 판정 기준 = 기획 결정: 연차는 이월분/생성분 사용 순서가 없으므로 **다음 귀속연도 잔여가 이월 일수만큼 남아 있지 않으면 정산 취소 자체를 에러로 막고**, 충분하면 정산 취소 연도에 이월분이 잔여로 돌아오는 대신 **다음 귀속연도 이월 일수에서 회수**. 기존 구현(차년도 이월 유지 → 쓸 수 있는 연차가 늘어남)은 수정 대상으로 결정. **코드 반영 확인**: 차년도 연차가 정산됐으면 에러, 차년도 행이 2건 이상이면 에러, 이월 0이면 바로 취소, 플러스 이월이면 (차년도 부여 − 사용) < 이월분일 때 에러, 통과하면 이번 정산에서 넘어간 이월분만큼만 차감(전액 0 초기화 아님) 후 의무/비의무 재분배 (`be:service/leaveadmin/AnnualLeaveSettlementService.prepareLeaveCrtToCancel`). 연차 외 휴가는 "이월한 휴가를 이미 썼으면 정산 취소 불가" — Slack #ch-plan 2025-12-04 (https://hcgtheplus.slack.com/archives/C02VCP9MBQV/p1764832416057689?thread_ts=1761704202.867549&cid=C02VCP9MBQV)

### 연차 수동등록 (관리자 등록 휴가)

[연차 수동등록] → "직접 입력하여 등록" / "엑셀 파일로 등록" 선택

**직접 입력**:
- 휴가 유형 입력 → 등록 대상 + 휴가일 disabled 해제
- 휴가일 입력 → 선택한 범위의 날짜만큼 사용 시간 입력 항목 노출
- **사용 시간 밸리데이션 7종** (화면 문구):
  - "차감 시간을 입력합니다."
  - "휴가는 30분 단위로만 사용가능 합니다."
  - "시작 시간을 입력합니다." / "종료 시간을 입력합니다."
  - "시작 시각과 종료 시각이 같습니다."
  - "종료 시각이 시작 시각 전입니다."
  - "차감 시간을 시작 종료 시각으로 계산한 시간 보다 같거나 작게 설정합니다."

**저장 결과 분기** — 백엔드가 실패 건을 4분류로 돌려줌 (`be:service/leaveadmin/LeaveManagementService.buildDirectLeaveResultDto`):

| 분류 | 화면 라벨 | 등록 가능? |
|---|---|---|
| `duplicateLeaveMembers` | 중복 휴가 | 불가 — 자동 제외 |
| `noAnnualLeaveMembers` | "연차 미생성(1년 미만 포함)" | 불가 — 자동 제외 |
| `lackLeaveMembers` | "1년 미만 연차 부족" | 불가 — 자동 제외 |
| `exceededAnnualLeaveMembers` | "연차 부족" | **처리 방식 선택 가능** ([초과 사용으로 등록] / [제외하고 등록]) |
| `otherFailedMembers` (마감·정산 등) | "근무가 마감되었거나 휴가 정산이 완료된 내역이 포함되어 있습니다. …" | 전체 중단 ("휴가 등록 실패 안내") |

모달 흐름 (`ad:...usage_record_tab/contents/leave_registration_dialog/DirectRegistrationForm.tsx`):

| 상황 | 모달 |
|---|---|
| 전부 등록 가능 | 모달 닫힘 + 스낵바 "등록을 완료하였습니다." |
| 전부 불가(중복·미생성·1년 미만 부족만) | "휴가 등록 실패 안내" — 확인만 가능 |
| 정상 + 불가 혼합 | "일부 휴가 등록 실패 안내" → [이어서 진행] |
| "연차 부족" 포함 + 정상 건 있음 | [초과 사용으로 등록] · [제외하고 등록] 둘 다 |
| "연차 부족"만 남음(정상 건 없음) | [초과 사용으로 등록]만 |

- "연차 부족" = 등록 사용시간 > 잔여 이면서 ① 초과 사용 허용 안 함 또는 ② 허용 한도 초과. [초과 사용으로 등록]은 한도를 넘겨 **강제 등록**(`allowExceededAnnualLeave=true`). 최종 확인에 "이 중 연차 초과 사용 등록은 n건 입니다." 표시
- **(2026-11-05 해소) 1년 미만 연차 초과 사용 모순 정리**: ~~"연차 부족만 (1년미만 제외) → [초과 사용으로 등록]" vs "초과 사용은 정상연차 전용"~~ → 2026-09-17 이후 1년 미만 연차에도 **연차 제도별 초과 사용 옵션**이 생겼음 (`hcgtheplus/optimiz-time#1642`, `hcgtheplus/talenx-admin#4375`, 기본값 꺼짐).
  - 옵션 **꺼짐**: 1년 미만 연차 부족은 "1년 미만 연차 부족"으로 분류돼 등록 불가 (기존 동작 그대로)
  - 옵션 **켜짐 + 한도 이내**: 그냥 등록됨 (초과분은 사용일을 덮는 도래 생성분 중 사용종료일이 가장 늦은 건에 음수 잔여로 기록)
  - 옵션 켜짐 + **한도 초과**: "연차 부족" 분류 → [초과 사용으로 등록]으로 강제 가능. 단 강제 등록도 **옵션 꺼짐은 우회하지 않음**, 얹을 도래 생성분이 없으면 불가 (`be:pojo/leave/MonthlyAnnualDirectDeductionCalculator.evaluateNewItem`)
  - 연차 외 휴가에는 여전히 초과 사용 없음 (`be:CalcLeaveService` "TODO) 연차외휴가 초과사용여부 확인")
- 확정 시: "{{name}}님 등 n건의 수동 휴가를 등록합니다.(적용일 : YYYY.MM.DD)"

**엑셀 등록**: 위 직접 입력과 동일한 분기. 추가로 **근무 마감된 일자 포함 시 업로드 불가** + 안내 문구. 비밀번호 걸린 파일은 "비밀번호 해제 후 업로드 해주시기 바랍니다."

## 연차 계산 핵심 룰 (화면 해석용)

`_learnings/2026-07-29-annual-leave-concept-map.md`의 코드 검증 사실 (2026-11-05 dev 재확인):

- **차감 순서 = 사용 종료일이 빠른 생성분부터** (만료 임박 우선, 귀속연도 순 아님) — `be:service/leaveuse/CalcLeaveService.java:107,136,541`
- **1년 미만 연차의 귀속연도(`CRT_YY`) = 연차기산일이 속한 회계연도** (정상연차는 작업 기준 연도). 단 선부여(`evmCrtMth=BF`)면 작업 연도 — `be:LeaveCreationService.java:1518–1600`. "월차가 해당 귀속연도로 조회하면 안 나온다" 문의의 원인
- **보유 사용분(`USE_M_CNT`)에는 신청중(미승인) 분이 없음**. 계산 중엔 신청중도 잔여를 막지만 저장은 확정분만
- **재계산(규칙 변경·조정·취소 배치)은 초과 사용 제한을 우회** — 신규 신청은 막혀도 이미 초과된 상태는 보존
- 잔여 마이너스 합산 표시는 사양 (예: 2025 −2일 + 2026 15일 → 13일). 연도별 조회로 구분
- 보유현황의 "사용기간"은 생성 건 단위 요약. 기간별 사용 이력은 연차 사용 현황 탭에서 확인 (반복 문의)
- 정산 후 재생성 보존 기준은 `IS_CLOSED`(마감 여부)
