# 연차기산일 변경 시 기존 연차와의 정합성 공백 (2026-07-10)

## 재현 시나리오 (두현님 제보)

1. 1년 미만 연차 생성
2. 연차 조정에서 첫 달 연차의 사용 시작일을 입사일로 조정
3. 구성원 정보에서 연차기산일을 입사일 **이후**로 입력

→ 이후 해당 구성원은 **연차 조정만 불가**, 사용/마감/정산 등은 전부 가능.

## 원인 — 경로별 기산일 검증 비대칭 (코드 검증 완료)

| 경로 | 기산일 검증 | 근거 |
|------|------|------|
| 연차 조정 화면 (어드민 프론트) | ✅ 사용시작일 < 기산일이면 에러 → [적용] 비활성 | `ad:src/components/attendance/leave/management/contents/annual_leave_summary_record_tab/edit/index.tsx:335` |
| 연차 조정 API (백엔드) | ❌ 포맷/시작>종료/귀속연도만 검증. 입사일·기산일 체크 **없음** | `be:service/leaveadmin/LeaveManagementService#leavePaymentValidationCheck` (L4412–4446) |
| 구성원 정보 기산일 저장 | ❌ 날짜 포맷만 검증. 기존 생성 연차와 정합성 체크 **없음** | `be:service/setting/MemberInformationService#updateMembers` (L103–106) |
| 휴가 사용 / 마감 / 정산 | ❌ 기산일 미참조 — TM_LEAVE_CRT의 useStaYmd~useEndYmd(생성 시점 스냅샷) 기준 동작 | service 레이어에서 `annualLeaveBaseYmd` 참조는 LeaveCreationService + MemberInformationService 뿐 (전체 grep) |

핵심: **기산일은 연차 생성 시 근속연수 계산에만 쓰이는 값** (`be:vo/MemberVo.java:40` 주석: "연차생성시 근속년수 계산할 때 가장 우선순위를 두는 날짜"). 생성된 연차의 사용기간은 스냅샷이라 기산일 사후 변경이 소급 반영되지 않음 → 사용/마감이 되는 건 이 설계의 일관된 결과.

## 왜 "조정만" 막히는가

조정 화면의 `useEffect` (edit/index.tsx:305–362)가 **선택된 모든 1년미만 행**의 기존 `useStaYmd`를 **현재 기산일**로 재검증. 사용자가 사용시작일을 건드리지 않아도 기존 값이 기산일보다 앞서면 에러로 잡혀 `applyDisabled` → 지급/차감 포함 조정 전체 불가.

## 판단

- 사용/마감 가능 자체는 스냅샷 설계상 자연스러운 결과.
- 다만 다음 2가지는 의도된 정책이라기보다 공백으로 보임:
  1. 구성원 정보에서 기산일 변경 시 기존 연차 데이터와 충돌 경고 없음
  2. 조정 화면이 미변경 행까지 재검증해 무관한 지급/차감 조정까지 전부 봉쇄
- 검증이 프론트에만 있어 API 직접 호출 시 백엔드는 통과함 → 정책이라면 백엔드에도 있어야 함.
