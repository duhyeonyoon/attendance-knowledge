> **메뉴** 근무 신청 › 연장/야간 근무(사후)
> **진입** 출퇴근 위젯 [근무신청] › "연장/야간근무(사후) 신청"
> **문서유형** "연장/야간근무(사후) 신청" / "연장/야간근무(사후) 취소 신청"
> **사용자** 구성원(신청자) · 결재자

## 1. 개요
이미 지난 근무일(휴일 제외)에 한 연장근무·야간근무를 **사후에** 승인받는 신청서입니다. 어드민이 근무그룹별로 사후 신청서를 사용으로 켜야 보이며(기본값 미사용), 연장·야간 허용이 '승인 시에만'인 그룹에서 켤 수 있습니다. 입력 방식과 시간 계산은 [연장/야간근무(사전) 신청](./overtime.md)과 같고, 고를 수 있는 날짜가 "오늘 이전의 휴일 아닌 날"입니다. 승인되면 사전 승인과 똑같이 근무 집계에 반영되며, 실제 출퇴근 기록과 겹치는 시간만 연장/야간으로 인정됩니다.

## 4. 정책 · 비즈니스 룰
1. 대상은 **현재 근무 귀속일 이전의 휴일이 아닌 날**(근무일·휴무일). 휴일의 사후 근무는 [휴일근무(사후) 신청](./holiday-work-post.md).
2. 메뉴 노출은 사후 신청서 사용 여부만 봄. 사후 신청서는 근무그룹별로 어드민이 켜야 함(기본 미사용), 연장 또는 야간 허용이 '승인 시에만'일 때 켤 수 있음.
3. 저장 시점에는 신청 대상일의 근무그룹 설정으로 다시 확인. 연장 불가·야간 불가 설정이면 사전 신청과 같은 이유로 거절.
4. 당일 과거 시각 정책 미적용, 고정출퇴근제 시작 시각 기본값 없음 (실제로 한 시간을 입력).
5. 시간 겹침은 **사전·사후 연장/야간 신청을 합쳐서** 판정 (신청일 전일~익일, 요청중·승인 건). 휴일근무 신청과는 비교하지 않음.
6. 최대 초과근무 한도: 근무그룹 연장근무 근무시간 포함여부가 '포함'이면 이미 집계된 실제 연장시간만큼은 추가 차감하지 않고, 그 외에는 신청 연장시간 전체를 차감. 잔여가 이미 음수면 차단. (화면은 정책과 무관하게 신청 시간을 잔여와 비교 — 7. 확인 필요)
7. 최소 초과근무시간은 신청서 1건 단위 (근무일/휴무일 기준).
8. 승인되면 사전 승인과 동일하게 집계되고 승인 시간 ∩ 실제 출퇴근 기록만 인정 → 출퇴근 기록이 없으면 인정 시간 없음.
9. 사전 승인과 달리 승인 시 출퇴근 기록을 만들거나 근무중 종료 알림을 보내지 않음.
10. 마감된 일자는 신청·승인·취소 신청·취소 승인 모두 불가.
11. 승인 후 취소는 취소 신청서로만 가능.

- **승인돼도 실제 근무한 시간만 인정**: 승인 구간과 실제 출퇴근 기록이 겹치는 시간만 인정되며, 출퇴근 기록이 없는 날은 승인돼도 인정 시간이 없습니다 (기획 확인 2026-11-05).
- **한도 초과 시 신청 차단**: 사후 신청도 최대 초과근무 한도를 넘으면 신청 단계에서 막습니다. 요청중인 사후 신청 시간은 사전 신청의 한도 계산에도 포함됩니다.

- **허용 설정과 신청서 사용 여부 (기획 확인 2026-11-05)**: 구성원이 소속된 근무그룹은 설정을 수정할 수 없고, 허용 옵션을 바꾸려면 그룹을 복제해 새 그룹으로 옮깁니다. 허용 옵션이 '승인 시에만'이 아니면 어드민 근무 신청서 관리에서 해당 신청서 행이 비활성되며 툴팁으로 활성화 조건을 안내합니다. 사후 신청서는 기본 '사용 안 함'이라 관리자가 켜야 합니다. 신청서 노출은 오늘 소속 근무그룹 설정 기준입니다.

## 7. 확인 필요
- 화면의 최대 초과근무 검증이 근무시간 포함여부 '포함' 그룹에서 서버보다 엄격하게 막는지 — 기획 기준은 "한도 초과 시 신청 단계에서 막는다"(화면 동작과 일치). 서버가 허용하는 경우가 실제로 있는지 스테이징 확인 필요
- 결재 문서 상세에서 마감된 일자의 승인/취소 버튼이 미리 비활성되지 않고 눌러야 막히는 것이 의도인지 (다른 신청서는 미리 비활성)
- 자정 직후(근무 귀속일이 아직 전날인 시간대)에 전날을 고르면 서버에서 거절되는지
- 연장/야간근무(사후) 신청 문서를 삭제할 때 신청서 쪽 삭제 처리가 정상 동작하는지 (삭제 처리 연결이 없어 실패 가능성 — 확인 필요)
