# product/ — 기능 명세 문서

각 .md 파일은 **실제 메뉴의 한 페이지**를 다룹니다 (2026-11-05 재구성). 폴더 구조가 메뉴 구조와 같습니다.

```
product/
├── admin/                 ← 어드민 (ap-tx) 근무관리 탭
│   ├── module-setting/    ← 모듈 설정 (구성원 정보·조직·직책) + overview(모듈 설정·권한 공통)
│   ├── authority/         ← 권한 (직책자·서브어드민)
│   ├── work/              ← 근무 (근무 설정 ~ 개인 근무 스케줄 관리, 8페이지)
│   ├── leave/             ← 휴가 (휴가 설정 ~ 연차 촉진, 6페이지) + overview(휴가 도메인 공통)
│   ├── old-data/          ← 과거 데이터 관리 (근무·휴가)
│   └── etc/               ← 근무관리 메뉴 밖 (연동)
├── user/                  ← 사용자 (app-tx)
│   ├── home/              ← 통합홈 위젯 (출퇴근 위젯·근무 현황·근무 요약·기타 위젯)
│   ├── attendance/        ← 근무관리 탭 7페이지
│   └── applications/      ← 근무 신청서 드로어 7종 + overview(신청서 공통)
└── _legacy/               ← 재구성 전 묶음 문서 원본 (참고용, 사이트 비노출)
```

**새 페이지를 쓸 때**: 메뉴 위치에 맞는 폴더에 만들고, 상단에 `sidebar.order`(메뉴 순서)와 메뉴/URL/탭 인용 블록을 둡니다. 여러 페이지가 공유하는 내용은 그 폴더의 `overview.md`에 둡니다. 메뉴 ↔ 문서 맵은 `index.md` 상단 표를 갱신하세요.

## 문서 템플릿

각 페이지 문서는 다음 구조를 권장:

```markdown
# <기능 이름>

## 개요
- 한 줄 설명
- 사용자 / 어드민 어느 쪽 기능인지
- 진입 위치 (URL / 메뉴 경로)

## QA 체크리스트 출처
- 파일: `repo/.claude/qa-checklist/attendance.md`
- 라인: L<start>–L<end>

## 코드 위치
- 프론트:
  - `pp:src/...` 또는 `ad:src/...`
- 백엔드 (관련 API/서비스):
  - `be:com/hcg/optimiz/time/...`
- 관련 DB 테이블:
  - `TM_*`

## 기능 상세

(체크리스트 항목을 의미 단위로 재구성. 단순 복붙 ❌, 분류와 인덱싱 ⭕)

## 비즈니스 룰
- (이 기능과 직접 연결된 룰. 일반 룰은 `domain/business-rules.md` 참조)

## 알려진 제약 / 미구현 / 임시 동작
- (체크리스트 안의 "임시 동작", "예정", "개발 필요" 같은 표현 추출)

## 관련 신청서 / 다른 기능과의 연계
- (워크플로우 연결, 알림 연동 등)

## [TBD]
- (확인 필요 사항)
```
