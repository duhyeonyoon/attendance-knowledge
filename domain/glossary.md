## 근무 시간 / 집계

| 용어 | 설명 |
|------|------|
| 회계연도 시작일 | 근무 1년의 첫 날짜 (연차 근속 계산 등) |
| 한 주의 시작 요일 | 주 52시간/주단위 휴가 계산 기준 |
| 표준근무시간 / 소정근무시간 | 정규 근무 시간 |
| 실근무 | 실제 근무한 시간 |
| 잔여근무 | 소정근무 - 실근무 |
| 최소 근무시간 | 일부 클라이언트 커스텀 (예: 엑셀세라퓨틱스) |
| 정산기간 | 근무시간 합산 단위 (주/월) |
| 근무 마감 | 일정 기간 근무 데이터 확정 (이후 변경 불가). 단위: 구성원 × 일자. 실행 단위: 근무그룹 × 기간 |
| 일괄 마감 | 어드민이 회사·근무그룹 다중 선택 + 기간(+선택 메모)로 실행. 적용일은 표시용(오늘, 미전송). `POST /time/close-work-data/close-work-bulk` |
| 마감 이력 | `TM_CLOSE_WORK_DATA_HISTORY` (마감 구분 `CLOSE_BULK`/`REOPEN_BULK`, 해제 이력은 `SOURCE_HISTORY_ID`로 원본 참조) — 마감 실행 1건당 1 row, 적용 그룹/구성원 다대다 관계 |
| 마감 적용 구성원 | 1건의 마감 이력에 해당하는 구성원 목록 (별도 화면) |
| `closeYn` | 일자별 마감 여부 (`Y`/`N`). 집계 테이블(`TM_DD_*_AGGR`)에 컬럼으로 존재 |
| `isClosed` | `closeYn === "Y"`를 프론트에 boolean으로 노출 |
| `CheckWorkDataIsClosedDto` | 마감 여부 확인용 백엔드 DTO. 다른 영역(출퇴근내역 편집, 신청서 검증)에서 호출 |
| 마감 해제 | 마감 내역 탭 "일괄 해제" — `PUT /time/close-work-data/close-work-bulk/reopen`, 이력 단위 해제 (REOPEN_BULK 이력 추가). 개별 마감/해제는 코드값만 존재 |
| 집계 | DD_/MM_/PERIOD_ — 일/월/기간 단위 집계 |
| **확정 근무시간** | 출퇴근 기록으로 계산된 유효 근무시간 (출퇴근만) |
| **합산 근무시간** | 확정근무 + 근무인정 기타근무 − 휴가 (중복 구간 제외) |
| **인정 근무시간** | 확정근무 + 근무인정 기타근무 + 근무인정 휴가 (중복 구간 제외) |
| **근무시간 산정 우선순위** | 휴가 > 기타근무 > 출퇴근 (같은 시간대 중복 시 우선순위 높은 것만 인정) |
| 자동 일근무집계 | 이벤트 기반(Kafka topic `time-daily-aggregation` → `AggregationListener`, 프로듀서 12곳+: 위젯 퇴근/어드민 수정/신청서 승인·취소/`DailyAggregationEventService`) + `TimeAggrBatchJob` 스케줄러(직접 호출, Kafka 미경유). 상세: `_learnings/2026-07-15-aggregation-kafka-flow.md` |
| 수동 일근무집계 | 어드민이 `PUT /time/aggr/manual-aggr/daily` 로 즉시 트리거 |
| 보정 기록 | `TM_INOUT_REG_ADJST_DTL` — 어드민이 직접 수정/삭제 시 추가되는 보정 row (raw 데이터 삭제 X) |
| 어드민 직접 삭제 (출퇴근) | 실제 row 삭제가 아니라 무효화 기록 생성 → 사용자 화면에 "누락"으로 표시 |
| 등록 방식 | 출퇴근내역 컬럼 — `어드민 변경` 등 (사용자 본인 입력 vs 어드민 입력 구분) |
| `hasModifiedWorkRecord` | ~~어드민 수정 여부~~ → 해당 일자에 **승인 완료된 (통합) 근무내역 변경·출퇴근 내역 변경 신청** 존재 여부. true면 출퇴근 위젯에서 출근/퇴근 대신 [근무 내역 변경] 버튼 (차단 아님) |
| `hasAdminModifiedWork` | 어드민 직접 수정 여부 — 신청서 기준일 조회 응답. true면 신청서에서 경고 + [요청] 비활성 |
| `registeredByAdmin` (UI 메시지) | "해당 근무는 별도의 신청/승인 과정 없이 관리자에 의해 등록되었습니다." (locale key) |
| 어드민 수정 후 차단 메시지 | 사용자가 어드민 수정 날짜에 변경 신청 시도 시: "해당 일자의 근무내역은 어드민이 수정 및 확정하였습니다." (경고 + [요청] 비활성). ~~"관리자에 의해 수정된 내역이…"~~는 코드에 없는 문구 |

### 자정 cutoff 동적 계산 (백엔드)

`be:com/hcg/optimiz/time/common/util/validworkday/ValidWorkDayResolver`의 두 상수:

- `STANDARD_HOUR_BY_VALID_WORK_DATE = 6` — 시스템 기본 출퇴근 기준 시간 (06:00)
- `DIFF_TIME_AVAILABLE_TO_WORK = 3` — 계획 출근시각 -3시간부터 출근 가능

규칙:
- 고정 출근시간 있는 근무일: **계획 출근시각 - 3시간**부터
- 자율 / 휴일 / 계획 없음: **시스템 기본 06:00**
- 야간 근무조 익일 퇴근: 전/당/익일 근무계획 모두 봐야 정확한 판정 가능

> 이전 5시 cutoff는 deprecated. 현재는 위 동적 규칙 사용.

## 근무 계획 / 스케줄 / 템플릿 — 핵심 용어 정리 ⭐

> **2026-05-13 두현님 정정**:
> - **근무 스케줄 = 근무 계획** (동의어, 같은 말. UI에 따라 달리 표현)
> - **근무 계획의 종류 = 근무 템플릿** (재사용 가능한 "타입")

```
[근무 템플릿]                  ← 종류 정의 (재사용 가능 타입)
   예: "주간 9-18", "야간 22-6", "휴일 템플릿"
        ↓ (적용)
[근무 계획 = 근무 스케줄]      ← 특정 일자 × 구성원에 적용된 인스턴스
```

| 용어 | 의미 | 코드/DB |
|------|------|------|
| **근무 템플릿** | 근무 계획의 종류 (재사용 가능 타입) | 어드민 #5 § 4, `TM_DD_WORK_PLAN` (마스터 row) |
| **근무 계획** = **근무 스케줄** | 특정 일자/구성원에 적용된 계획. 두 용어는 같음 | `workPlan`, `WorkPlan` AttendType, `TM_*_WORK_PLAN` |
| **그룹스케줄** | 근무그룹 단위로 적용된 근무 계획 | `TM_WORK_GRP_DD_WORK_PLAN` |
| **개인스케줄** | 구성원 개인 단위로 적용된 근무 계획 (그룹스케줄보다 우선) | `TM_EMP_WORK_PLAN` |
| **근무그룹 vs 휴가그룹** | 근무 정책 vs 휴가 정책. 같은 구성원이 다른 그룹 가능 | `WorkGrpVo` / `LeaveGrp` |
| **근무 템플릿 fork** | 클라이언트 공통 템플릿을 그룹에서 수정 시 새 row로 분리 (원본 보존) | (어드민 #5 § 4) |
| **개인 근무 템플릿 관리** = **개인 근무 스케줄 관리** | 개인별 근무 계획(스케줄)의 종류 관리. `personal_work_template_management` (의도된 명명, template 표현) | 어드민 #11 |
