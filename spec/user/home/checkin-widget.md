> **메뉴** 통합홈 › 우측 출퇴근 카드 (출근/퇴근 버튼 · 근무 신청 · 근무 현황)
> **사용자** 사용자(구성원 본인)

## 1. 개요

사용자가 **출근 · 퇴근 · 자리비움 · 복귀 · 재출근**을 직접 기록하는 핵심 위젯입니다. 통합홈 메인과 근무관리 › 내 근무 화면 두 곳에 같은 기능으로 노출됩니다.
출퇴근 시점에 근무지(위치) 확인, 출근 인정 시각, 근무 그룹의 휴일·야간·연장 근무 허용 설정, 사전 신청 승인 여부, 근무 마감 여부를 함께 검증하며, 조건에 맞지 않으면 차단하거나 안내문을 띄우거나 승인 요청(출/퇴근 요청)으로 전환합니다.

## 3. 기능 상세

### 3.1 근무 상태별 버튼

| 근무 상태 (화면 의미) | 노출 버튼 |
|---|---|
| 출근 전 | **출근** |
| 근무 중 | **자리비움** + **퇴근** |
| 자리비움 중 | **업무 시작** (복귀) |
| 자리비움 복귀 | 복귀 처리 직후 근무 중 화면으로 돌아감 (추정) |
| 퇴근 완료 | **재출근** |

**우선 분기** — 아래 중 하나라도 해당하면 상태와 무관하게 모든 출/퇴근 버튼 대신 **"근무 내역 변경"** 버튼만 노출합니다.

| 조건 | 버튼 상태 | 상태 문구 |
|---|---|---|
| 퇴근 기록만 있고 출근 기록이 없음 (예: 출근 요청 반려 후 퇴근) | 활성 | "근무 내역 변경이 필요합니다" |
| 해당 일자에 승인 완료된 근무내역 변경 / 출퇴근 내역 변경 신청이 있음 | 활성 | (근무 상태 문구) |
| 근무내역 변경 / 출퇴근 내역 변경 신청이 진행 중 | **비활성** | "근무 내역 변경 요청중 입니다." (시간 영역 숨김) |

- [근무 내역 변경] 클릭 시 근무 그룹이 사용하는 신청서 중 **출퇴근 내역 변경**을 우선 열고, 없으면 통합 근무내역 변경을 엽니다.
- 근무 그룹이 두 신청서를 모두 사용하지 않으면 버튼이 비활성화되고 툴팁 "통합 근무내역 변경과 출퇴근 내역 변경 신청서를 모두 사용할 수 없습니다. 어드민에 문의해 주세요."가 표시됩니다.
- **관리자(어드민)가 직접 수정한 일자**는 위젯이 따로 구분하지 않습니다(버튼 노출 조건 아님). 그 일자로 변경 신청서를 작성하려 하면 신청서에서 "해당 일자의 근무내역은 어드민이 수정 및 확정하였습니다."로 차단됩니다.

**근무 기록 방식(근무 그룹 설정)에 따른 노출**

| 근무 기록 방식 | 출/퇴근 버튼 | 시간 표시 |
|---|---|---|
| 출퇴근 기록 (기본) | 노출 | 측정된 시간 |
| 근무 계획 시간 사용 | **미노출** | 측정 시간 대신 "근무 중" 텍스트 |
| 외부 시스템 연동 (현재 세콤만 해당) | **미노출** | 일반 그룹과 동일 (외부 시스템이 기록한 값 기준) |

현재 접속 채널(모바일 앱 / PC)에서 출퇴근 등록이 허용되지 않도록 설정된 경우에도 출/퇴근 버튼이 노출되지 않습니다.

근무 그룹에 "근무시간 화면 표시 안 함"이 설정된 경우 근무시간을 표시하지 않습니다 (특정 고객사 요청 기능).

## 4. 정책 · 비즈니스 룰

### 4.1 사전 차단 (버튼 클릭 직후, 모달 열기 전)

| 조건 | 결과 |
|---|---|
| 근무 그룹 휴일근무 = **불가** + 오늘이 휴일 + 출근/재출근 클릭 | 출근 불가 안내 후 **차단** |
| 근무 그룹 야간근무 = **불가** + 현재 22:00~06:00 + 출근/재출근 클릭 | 출근 불가 안내 후 **차단** |

### 4.2 휴일 · 야간 · 연장 근무 허용 설정별 동작

근무 그룹은 휴일·연장·야간 근무 각각을 **자유 허용 / 승인 시에만 / 불가** 중 하나로 설정합니다 ([근무 그룹 설정](../../admin/work/group-setting.md)).

| 구분 | 설정 | 출근 시점 | 퇴근 시점 |
|---|---|---|---|
| 휴일근무 | 불가 | 출근 불가 안내 (차단) | 출근 후 그룹/스케줄 변경으로 불가가 된 경우 안내문 후 퇴근 가능 |
| 휴일근무 | 승인 시에만 | 승인된 사전 휴일근무 신청 없으면 안내문 후 출근 가능 / 있으면 정상 처리 | 동일 |
| 야간근무 (22~06시) | 불가 | 출근 불가 안내 (차단) | 안내문 확인 후 퇴근 가능 |
| 야간근무 (22~06시) | 승인 시에만 | 승인된 사전 신청 없으면 안내문 후 가능 | 동일 |
| 야간근무 예외 | 승인 시에만 + "근무계획시간 외 모든 시간 = 연장근무" 설정 | 계획 출근시각 전 조기출근(연장근무 출근)에는 안내문 **미표시** (예: 09~18시 그룹의 07시 출근) | — |
| 연장근무 | 불가 | 연장시간대 출근은 서버가 **차단** (화면 사전 안내 없음, 아래 주의) | 연장시간대 퇴근 시 미승인 안내 다이얼로그 후 퇴근 가능 |
| 연장근무 | 승인 시에만 | 연장시간대 + 승인 없음 → 미승인 안내 다이얼로그 후 가능 | 동일 |
| 연장근무 | 초과근무 시간 제한 설정 | 제한 초과 시 미승인 안내 다이얼로그 | 동일 |
| 공통 | 최대 근무시간 제한 초과 | 미승인 안내 다이얼로그 | 동일 + "소정근무시간을 초과했습니다." 안내문 |

"승인 시에만" 설정의 "안내문"은 미승인 안내 다이얼로그(U-HOME-CHK-11)입니다. 휴일·야간·연장 **불가** 정책 위반은 출근 시에는 차단, 퇴근 시에는 기록 보존을 위해 안내 후 허용합니다. 차단은 실제 출근 등록 시점에 서버가 판정하고, 사전 확인 단계에서는 "승인 시에만" 미승인 안내만 띄웁니다 (기획 확인 2026-11-05).

> **주의 — 연장근무 불가 + 연장시간대 출근 (현재 구현)**: 서버는 출근을 거절하지만 화면에 전용 안내 문구가 없어, 출근 버튼을 눌러도 아무 안내 없이 상태가 바뀌지 않습니다. 화면 안내는 개발 예정 항목입니다. 현재 어드민의 '연장 불가' 옵션은 신규 선택이 막혀 있어(개발 전) 예전에 '불가'로 저장된 근무 그룹에서만 발생합니다 (기획 확인 2026-11-05).

사전 신청은 [연장/야간근무 신청](../applications/overtime.md), [휴일근무 신청](../applications/holiday-work.md)에서 승인받습니다.

### 4.3 근무지(위치) 확인

| 위치 확인 결과 | 의미 | 처리 |
|---|---|---|
| 근무지 반경 내 | 등록 근무지와의 거리가 근무지 허용 반경(m) 이내 | 정상 출/퇴근 |
| 근무지 외 | 반경 밖 | "위치 확인 필요" 안내("출근 가능 지역이 아닙니다. 현재 위치에서 출근 요청 하시겠습니까?") → 확인 시 **출/퇴근 요청 모달** → 승인 요청 |
| 위치 확인 불가 | 위치 정보를 얻지 못함 | 근무지 외와 동일 (위치 확인 사용 시) |
| 위치 권한 거부 | 브라우저/앱 위치 권한 거부 | 근무지 외와 동일 (위치 확인 사용 시). 이 요청은 위치가 없어 승인자가 위치를 확인할 수 없음 |
| 위치 확인 시간 초과(웹 10초) | 응답 지연 | U-HOME-CHK-12 안내 |

**검증 방식** (회사·접속 채널별 설정)

| 방식 | 근무지 외 판정 |
|---|---|
| 검증 없음 | 항상 정상 |
| GPS만 | GPS 반경 밖(또는 위치 확인 불가·거부) |
| IP만 | 등록 IP와 불일치 |
| GPS 또는 IP | GPS와 IP **둘 다** 통과 못할 때만 근무지 외 |
| 출퇴근 등록 불가 | 버튼 미노출 |

- 거리는 현재 좌표와 등록 근무지 좌표의 지구 표면 직선거리로 계산합니다.
- **예외**: 근무 그룹의 GPS 설정이 OFF이거나 등록된 출근지가 없으면 근무지 외 출퇴근을 그대로 허용합니다.
- 근무지 검증 옵션은 회사 설정·접속 채널(모바일 앱 / PC)에 따라 다르게 적용됩니다.
- **재택근무 확정일**과 **자리비움 후 업무 시작**은 위치 확인 대상이 아닙니다.
- 근무지 외 요청의 위치는 승인자가 3개월 이내에 확인할 수 있고, 확인 이력은 신청자의 [위치정보 제공 조회](../attendance/location-access-logs.md)에 남습니다.

### 4.4 출근 인정 시각

1. 근무 그룹에 출근 인정 시각을 설정할 수 있습니다.
2. 인정 시각 **이전** 출근 시 출근 기록은 실제 시각으로 남지만, 출근시간 옆에 info 문구가 표시되고 [실제 출근 ~ 인정 시각] 구간은 근무시간으로 인정되지 않습니다(조기출근 비근무).
3. 출근시간 고정 여부(정해진 시각 / 자유롭게)와 무관하게 동일하게 동작합니다.
4. 예상 퇴근시간에는 인정 시각 보정이 없습니다. 자유 출근 그룹은 실제 출근 기준으로 예상 퇴근시간이 계산되어 앞당겨져 보일 수 있습니다.

### 4.5 연장근무 · 소정근로시간 안내문

| 조건 | 안내 |
|---|---|
| 연장근무 = 자유 허용 + 근무 중 연장시간대 진입 | **주황색** "예상 퇴근 시간이 지났습니다." |
| 연장근무 = 승인 시에만 + 연장시간대 + 승인 없음 | **빨간색** "예상 퇴근 시간이 지났습니다." (상태 문구 강조도 빨간색) |
| 연장근무 = 불가 + 예상 퇴근시간 초과 | 위젯 안내문 **미표시**. 퇴근 시 미승인 안내 다이얼로그 |
| "근무계획시간 외 모든 시간 = 연장근무" 그룹 | 계획 출근시각 **이전**에는 위 안내 미표시 |
| "정산기간의 근무시간 합계가 기본 근무시간을 넘어가면 연장근무로 기록" 그룹 | 예상 퇴근시간을 넘어도 위 안내 **미표시**. 정산기간 잔여 소정근로시간이 0이면 주황색 "소정근무시간을 초과했습니다." |
| 최대 근무시간 제한 초과 (그룹 설정 무관) | 주황색 "소정근무시간을 초과했습니다." |
| 근무 계획 시간 사용 그룹 | 안내문 없음 |

### 4.6 자정 이후 (전날 근무 처리)

하루의 시작(cutoff) 시각 전까지는 전날 근무로 보고, 이후에는 새 날짜로 전환합니다.

| 근무일 유형 | cutoff 시각 |
|---|---|
| 고정 출근시간이 있는 근무일 | **계획 출근시각 − 3시간** (예: 09시 출근 → 06:00) |
| 자율 근무 / 휴일 / 근무계획 없음 | **06:00** (시스템 기본) |
| 전날이 고정근무일 + 당일이 휴일 | 전날 출근 가능 시각부터 24시간 동안 출근 가능 (예외) |

| 전날 상태 | cutoff 이전 화면 | cutoff 경과 후 |
|---|---|---|
| 출근O 퇴근X | "{현재날짜} OO시간 OO분째 근무 중 (출근일: {어제날짜})" + [퇴근] | 전날 = 퇴근 누락, 오늘 = 최초 출근 전 상태 |
| 출근O 퇴근O | "{현재날짜} OO시간 OO분 근무했습니다 (출근일: {어제날짜})" + [재출근] | — |
| 출근X 퇴근X | "{어제날짜} 출근전 입니다" + [출근] | — |

- 팀원 근무 현황도 같은 기준입니다 (어제 출근 후 미퇴근 팀원은 "근무중").
- 야간 근무조(예: 21시~06시 고정)의 익일 퇴근은 **전날** 근무계획 기준으로 처리됩니다.
- 근무일 판정은 서버가 한 곳에서 하며, 화면은 서버가 알려준 근무일을 그대로 표시합니다. 근무일이 오늘보다 이전이면 "출근일: {M월 D일(요일)}" 안내가 붙습니다.

### 4.7 기타

1. **근무 마감된 일자**는 출/퇴근 요청·승인·취소요청·취소승인 모두 불가합니다 ([근무 마감](../../admin/work/close-work-data.md)).
2. 출근/퇴근 후 팀원 근무 현황과 내 근무 캘린더의 오늘 셀이 갱신됩니다.
