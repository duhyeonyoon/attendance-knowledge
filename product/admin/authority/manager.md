# 직책자 권한

> **메뉴** 근무관리 › 권한 › 직책자 권한  
> **URL** `/attendance/authority/manager`  
> **원본** `product/_legacy/admin-system-entry.md`

권한 모델 전체(4단계 계층, 권한 결정 흐름)는 [모듈 설정·권한 공통](../module-setting/overview.md)을 보세요.

**2가지 권한 종류**:
- **직책자 권한** (Manager) — 직책 기반 자동 부여 권한
- **서브어드민 권한** (Custom) — 명시적 지정 권한 (담당자 + 권한 범위)

*원본 섹션: #4-1. 직책자 권한 (L81–101)*

## 메인 페이지

- 직책그룹 리스트
- 직책그룹명 아래에 포함된 **직책 표시**
  - 일립시스(`...`) 처리 시 **마우스 오버 → 툴팁**
- **인원수** 표시
- **X 아이콘** → 그룹 삭제: "삭제 요청" 컨펌 "직책자 권한 유형 '그룹명' 삭제하시겠습니까?" → "직책자 권한 유형 '그룹명' 삭제했습니다."
  - **(2026-11-05 해소) 해당 직책 보유자가 있어도 삭제 제약 없음** — 대상 직책 매핑 → 그룹 순으로 삭제하고 그룹 권한 회수 이벤트 발행 (`be:service/auth/TimeManagerAuthGroupSettingService.deleteMgrAuthGrpByMgrAuthGrpId:493-500`). 삭제된 그룹의 직책은 미부여 직책으로 돌아감
- [직책그룹 추가] 모달: 직책 그룹명 + 포함 직책(다중) — "직책 그룹명을 입력합니다." / "직책을 1개 이상 선택합니다." → "직책자 유형을 생성했습니다."
- 클릭 → 상세 페이지
- **미부여 직책** 클릭 → 직책그룹 추가 모달 (선택한 직책 자동 선택)

> **(2026-11-05 Slack 재검토) 직책자 권한 운영 원칙**
> - 사용자 화면의 매니저 기능은 **직책자 권한(직책 그룹 · 메뉴 · 범위)이 전부** — 별도 "매니저 권한" 없음. 조직장으로 지정만 해서는 권한이 생기지 않음
> - 개인 단위 예외 부여 불가 (직책 그룹 단위)
> - 구성원 근무의 **'일정' 탭은 권한과 무관하게 누구나 조회**, '현황' 탭과 요청 처리만 직책자 권한 필요
> - 근무스케줄 수정 권한도 직책자 권한으로 결정 (권한 없으면 본인 스케줄 읽기 전용)
> - 근거: Slack #cx 2026-08-31, #channeltalk 2026-10-20·10-23 (`_learnings/2026-11-05-resolve-user-attendance.md` Slack 재검토 표)

## 상세 페이지

**권한 설정 섹션 항목** (2026-11-05 코드 확인, `ad:src/components/attendance/authority/manager/detail/contents/AuthSetting.tsx`, `ad:src/locales/ko/sharedComponentAuth.json` `manager.*`):

| 항목 | 선택지 / 내용 |
|------|------|
| 직책 그룹명 | 텍스트 (필수 — "직책 그룹명을 입력합니다.") |
| 포함 직책 | 직책 다중 선택 (필수 — "직책을 1개 이상 선택합니다."). 다른 그룹에 이미 속한 직책은 불가 (백엔드: "권한 그룹에 맵핑되는 대상 직책은 중복될 수 없습니다. (직책명)") |
| **조직장 조건** | **제한없음** / **조직장만 권한 부여** — 툴팁 "포함 직책 중 조직장인 구성원에게만 권한을 적용하려면 설정합니다." (`be:CONST_TIME_AUTH.ENUM_HEAD_ONLY_GRANT_TYPE` = `NO_LIMIT` / `ONLY_ORG_HEAD`) |
| 권한 범위 | **본인 조직** / **본인 + 하위조직** (`ENUM_INFO_AUTH_SCOP` `ONLY_ROOT_ORG` / `INCLUDE_SUB_ORG`; 목록에는 `NONE`="없음"도 표시 가능) |
| 권한 설정 표 (구분 / 항목 / 권한) | 2개 고정 항목 (`be:dto/auth/TmMgrAuthItemDto.makeMgrAuthItemList`): **근무 › "구성원 근무 현황, 구성원 휴가 현황"** (`memberManagementYn` = JOB `MEMBER_MANAGEMENT`) / **근무스케줄 › "근무스케줄 작성"** (`indScheduleManageYn` = JOB `IND_SCHEDULE_MANAGE`) |

- 저장: 변경 없으면 "변경사항이 없습니다.", 성공 시 "직책자 유형변경이 완료되었습니다."
- 권한 항목은 YN 컬럼 나열 방식(동적 아님) — `be:TimeManagerAuthGroupSettingService:353` TODO
- 직책자 현황 표: No · 이름 · 사번 · 회사 · 조직 · 조직장 여부 · 직책, 필터 회사 + 이름

- **권한 설정 섹션** = [수정] 버튼 클릭 후 수정
- **포함 직책 / 조직장 조건 변경** → 직책자 현황 자동 업데이트
- **포함 직책 정렬** = 선택 순서 X, 기본 정렬 순서 (칩 정렬)
- 수정 중 [취소] → 초기값 복원
- **미부여 직책 추가 + 저장** → 미부여 직책에서 제거
- **직책자 현황 필터링** (이름 인풋: 엔터 또는 돋보기)
