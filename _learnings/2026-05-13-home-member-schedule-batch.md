## 큰 발견

### 1. 매니저 워크플로우의 일관 패턴 (U9 + U10)
**"요청 모아보기 + 일괄 승인/반려"** 패턴이 구성원 근무와 구성원 휴가 양쪽에 동일 적용:
- 빨간 dot + 갯수
- 여러 건 선택 후 일괄 처리
- 동시 처리 경합 시 실패 처리
- 통합홈의 "처리할 문서" 위젯과 짝 (다른 진입점, 같은 백엔드 처리)

### 2. 우선순위 룰의 일관성
attendance 도메인의 시간 우선순위가 곳곳에 반복:
- 휴가 시간 산정: 휴가 > 기타근무 > 출퇴근 (`KB:product/admin/leave/overview.md`)
- 구성원 근무 일정 표시: 휴가 > 기타근무 > 재택근무 > 근무계획
- 구성원 근무 현황 타임 표시: 요청중 > 취소중 > 휴가 > 기타
- 캘린더 셀의 우선순위 (`KB:product/user/attendance/my-work.md`)

→ **휴가가 항상 1순위** + 기타근무가 2순위. 다른 영역 deep-dive 때도 일관 확인.

### 3. 권한 분기 패턴
- U11 근무스케줄: 수정 권한 → 역할 기준 탭 + 수정 페이지
- U10 구성원 휴가 현황: 직책자 권한 → 권한 내 구성원
- U9 구성원 근무 현황: 직책자 권한 + 필터로 조직/구성원

권한 메커니즘 자체는 `KB:product/admin/work/group-setting.md` § "권한"에서 정의. 사용자 화면 곳곳에서 일관 적용.

### 4. 임시저장 패턴의 횡적 일관성
- 근무그룹 임시저장 (`tempSaveYn`)
- 휴가그룹 임시저장
- **근무스케줄 미확정** (이번 deep-dive에서 발견)
- 신청서 임시저장 (`CONST_APPLY_ACTION.TEMP_SAVED`)

같은 메타 패턴이 4개 영역에 적용. **확정 전 작업 보호 + 검토 시간 확보**.

### 5. 동적 cutoff 룰의 영역별 변형
- 출퇴근 자정 cutoff: 계획출근시각 - **3시간** / 6시 기본 (`ValidWorkDayResolver`)
- 휴가 신청 출근가능시간: 익일 출근시간 - **2시간** / 6시 기본

→ **-3시간 vs -2시간**은 의도된 차이. 출퇴근은 조기 출근 가능성 더 넉넉히, 휴가는 더 보수적.

### 6. 1년 미만 구성원 특수 처리
2가지 발견:
- **구성원 근무 상세 현황 (U9-3)**: 입사 1년 미만 → 입사 이후 데이터만
- **구성원 휴가 현황 (U10-2)**: 1년 미만 연차 → 귀속연도 다르더라도 한 행으로 통합 + 개별 기한
- 신입 입사자 관련 룰들 — 인사 연동 + 연차 정산 룰과 직결

### 7. 어드민 근무 누락 알림의 정교한 시나리오
- 조건 3개 (누락 + 미발송 + 변경신청 없음)
- 발송 중 사용자가 변경신청하면 **알림 발송 제외 모달**
- 동시성 처리 디테일이 잘 설계됨

### 8. 근무스케줄 수정 페이지의 UX 디테일
- 소프트키 단축 (숫자/Cmd+Z/Esc) — 매니저 효율
- 페이지 이탈 경고 (저장 안 한 데이터 보호)
- 필터 유지 (월 이동 후에도)
- 캘린더 내부 4개 이상 더보기 (UI 제약)
