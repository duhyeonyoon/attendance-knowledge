## 큰 발견

### 1. 권한 모델의 4단계 계층
명확히 정리됨:
```
총괄 (#3) → 직책자 (#4-1) → 서브어드민 (#4-2) → 일반 구성원
```
- 사용자 화면들의 권한 분기가 모두 이 계층에서 파생
- `KB:product/user/attendance/member-work.md` (직책자) / `KB:product/user/attendance/schedule.md` (수정 권한) 등

### 2. 인사 연동의 비대칭 룰
- **활성→비활성**: 양쪽 일관 (즉시 동기화)
- **비활성→활성**: 인사 연동 중이면 인사 발령으로만 (근무에서 임의 활성 불가)
- 이유: 인사 발령이 권위 있는 정보 소스

### 3. 다중회사 클라이언트 임시 제약 (또 발견)
2025.07.08 기준:
- 단일회사: 다중조직 선택 가능
- 다중회사: 회사 단위 전체조직만 선택 가능
- → 이전 deep-dive(`KB:product/admin/work/group-setting.md`)에서도 동일 임시 제약 발견. **회사-조직 관계 관리** 추가 후 해제 예정

### 4. 서브어드민 권한의 정교한 모델
- 권한그룹 → 담당자 → 권한 범위 (조직) → 범위내 구성원 (담당/추가/제외)
- 추가 구성원 vs 제외 구성원 분리
- 복구 시 범위 체크 후 분기 (담당으로 / 단순 삭제)

### 5. 과거 데이터 관리 = 별도 격리
- 일반 근무/휴가 데이터와 분리된 테이블
- 집계/정산에 영향 X (조회 전용)
- 데이터 마이그레이션 / 이력 보존 용도

### 6. 디렉토리 명명 불일치 (#11)
- UI/QA: "개인 근무 스케줄 관리"
- 코드: `personal_work_template_management` (template 표현)
- 또 하나의 작은 명명 헷갈림 발견 (DayOff = 휴일근무, HomeWork = 재택)

### 7. 개인스케줄의 3가지 출처
- 근무계획변경 신청서 승인 (사용자)
- 직책자 직접 입력/확정 (역할 기준 탭)
- 대체근무 신청서 승인 (사용자)
→ 모두 같은 데이터 모델(`TM_PSN_WORK_PLAN_APPL` 또는 `TM_EMP_WORK_PLAN`)에 저장

### 8. U13 연차촉진 강제 모달
- 사용시기 지정 통보 알림 팝업: 확인 전 다른 작업 차단
- UX적으로 강제 — 컴플라이언스 요구사항 추정

### 9. 위치정보 제공 조회 = 개인정보 보호 화면
- GDPR/개인정보보호법 대응
- 타인이 본인 위치 조회한 이력 확인
- 위치 정보 없으면 로그 X (불필요 트래킹 방지)
