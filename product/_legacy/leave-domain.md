# 휴가 도메인 (어드민 #12 + #13 + #14 + 사용자 U8)

## 개요

휴가는 attendance 안에서도 **별도의 큰 서브 도메인**. 4개 영역이 위계적으로 연결됨:

```
[어드민 #12 휴가설정]                          ← 마스터 데이터 정의
   ├─ 연차 제도 (Annual Leave Rule)
   ├─ 연차 정산 기준 (Annual Leave Operation Rule)
   └─ 연차 외 휴가 제도 (Non-Annual Leave Rule)
        ↓ (휴가그룹이 상속)
[어드민 #13 휴가그룹 설정]                     ← 정책 단위 (구성원 묶음)
   └─ 휴가그룹 + 휴가제도 매핑 + 구성원 매핑
        ↓ (구성원에게 적용)
[어드민 #14 휴가 지급 및 관리]                 ← 운영
   ├─ 연차 자동생성 / 수동 지급 / 조정 / 정산
   └─ 연차 외 휴가 지급 / 수동 등록 / 정산
        ↓ (사용자가 사용)
[사용자 U8 내 휴가]                            ← 신청·사용
   ├─ 잔여/예정/사용 기록 조회
   └─ 휴가 신청 (workflow → 승인)
```

## 휴가 도메인 데이터 모델

### 3 종류의 마스터 엔티티 (어드민 #12에서 정의)

| 엔티티 | 어드민 메뉴 | 백엔드 테이블 | 역할 |
|------|------|------|------|
| **연차 제도** | 휴가설정 > 연차 제도 | `TM_LEAVE_SYSTEM` (annual type), `TM_ANL_CRT_RULE` | 연차 부여 룰 (회계연도/입사일 기준, 연차 사용 시간대 등) |
| **연차 정산 기준** | 휴가설정 > 연차 정산 기준 | `TM_ANL_CM_RULE` 또는 별도 | 의무 사용, 이월, 보상 룰 |
| **연차 외 휴가 제도** | 휴가설정 > 연차 외 휴가 제도 | `TM_LEAVE_SYSTEM` (non-annual type) | 경조사/병가/기타 휴가 룰 |

### 휴가그룹 (어드민 #13)

| 엔티티 | 백엔드 테이블 | 역할 |
|------|------|------|
| **휴가그룹** | `TM_LEAVE_GRP` | 휴가 정책 단위 (구성원 묶음) |
| **휴가그룹-제도 매핑** | `TM_LEAVE_GRP_LEAVE_SYSTEM` | 그룹에 어떤 제도/정산기준을 적용할지 |

> 휴가그룹은 근무그룹과 별개. 같은 구성원이 다른 휴가그룹 + 다른 근무그룹에 속할 수 있음

### 운영 데이터 (어드민 #14)

| 엔티티 | 백엔드 테이블 | 역할 |
|------|------|------|
| **휴가 생성** | `TM_LEAVE_CRT` | 연차 자동/수동 생성 결과 |
| **휴가 지급 이력** | `TM_LEAVE_PAY_HISTORY`, `TM_LEAVE_PAY_HISTORY_ACCESS_TIME` | 지급 이력 |
| **휴가 사용** | `TM_LEAVE_USE`, `TM_LEAVE_USE_HISTORY` | 사용 기록 |

### 신청 데이터

| 엔티티 | 백엔드 테이블 | 역할 |
|------|------|------|
| **휴가 신청** | `TM_LEAVE_APPL`, `TM_LEAVE_APPL_DTL` | 사용자 신청서 |
| **휴가 취소 신청** | `TM_LEAVE_CANCEL_APPL` | 결재 완료 후 취소 신청 |

## § A. 휴가설정 (어드민 #12)

QA L798–872. 3개 서브 섹션 (각각 별도 페이지):

### A-1. 연차 제도 (Annual Leave Rule)

**페이지**: `/attendance/leave/base_setting/annual_leave_rule`

**핵심 설정**:
- **연차 부여 기준**: 회계연도 기준 / 입사일 기준 / 부여 안함
  - "부여 안함" 설정 시 1년 미만 연차/첫 회계연도 연차/연차 설정 모두 숨김
- **1년 미만 연차** (월차)
- **첫 회계연도 연차 설정** (회계연도 기준 선택 시)
- **연차 설정** (근속연수별 부여 일수) — 법적 표준 데이터 미리 입력됨, `법적표준 불러오기` 버튼으로 초기화 가능
  - 근속연수 입력 시 이전 행의 종료 연도 자동 변경
  - 이전 행보다 작게 입력하면 저장 불가
- **연차 사용 시간대**:
  - **자율**: 체크박스로 단위 선택 (시간/30분/종일 등). 모두 해제 시 "1개 이상 설정" 메시지
  - **고정**: 종일 + 추가 항목. 종일은 삭제 불가. 항목 정렬: 종일 > 차감시간 역순 > 시작시각 > 종료시각 > 항목명
    - 각 항목: 시작/종료 시각 + 차감시간
    - 시작=종료, 시작>종료 → 밸리데이션
    - 차감시간 > (종료-시작) → 밸리데이션
  - **자율+고정**: 둘 다 동일하게 동작

**룰 제약**:
- 이미 휴가그룹에 할당된 제도: 사용여부 → "사용 안함" 변경 불가 ("휴가그룹에 적용된 연차 제도는 사용여부를 변경할 수 없습니다.")
- 이미 할당된 제도 삭제 불가 ("휴가그룹에 적용된 연차 제도는 삭제할 수 없습니다.")
- 수정 상태 [취소] → 조회 상태로 전환 (페이지 이동 X)
- 추가 상태 [취소] → 페이지 이동 알림 → 리스트로

### A-2. 연차 정산 기준 (Annual Leave Operation Rule)

**페이지**: `/attendance/leave/base_setting/annual_leave_operation_rule`

**조회/생성/수정/삭제** 표준 CRUD:

- 생성 시: **연차 의무 사용 안함** 선택 → 의무 사용 일수 기준 / 잔여 처리 설정 불가
- 생성 시: **연차 전체 보상** 선택 → 연차 이월 여부 설정 불가
- 수정 제약: 이미 저장된 정산 기준은 **이름/메모/사용여부만 수정 가능** (룰 자체는 변경 불가)
- 삭제/사용여부 변경 제약: 휴가그룹에 매칭된 경우 차단 (연차 제도와 동일 패턴)

### A-3. 연차 외 휴가 제도 (Non-Annual Leave Rule)

**페이지**: `/attendance/leave/base_setting/non_annual_leave_rule`

**핵심 설정** (연차 제도와 유사하지만 추가 옵션):
- **연차 외 휴가 제도명** = **사용자용 / 어드민용 별도 설정** (어드민 화면에는 어드민용으로 노출)
- **부여 방식**: 옵션 선택 시 추가 입력 항목 활성화
- **기간 제한**: "제한" 선택 시 제한일자 정보 필수
- **휴일/휴무일 포함 여부**: 체크하면 근무계획상 휴일/휴무일에도 사용 가능
- **휴가 사용 시간대**: 연차 제도와 동일 (자율/고정/혼합)
  - **고정 > '종일' 체크박스 해제 시** 일반 항목처럼 항목명 수정 가능 (연차와 차이점)
  - **항목은 최소 1개 유지** (모두 삭제 불가)

> 연차 외 휴가는 **사용자에게 보이는 이름과 어드민이 보는 이름이 다를 수 있음** — 예: 사용자에게는 "특별 휴가"로, 어드민에게는 "직원 행사 보상휴가"로 명명 가능

## § B. 휴가그룹 설정 (어드민 #13)

QA L874–958. **근무그룹과 패턴이 거의 동일**합니다 (`KB:product/admin-work-group.md` 참고).

### 주요 동작

**메인화면**:
- 리스트 페이징 (서버 사이드)
- 최초 생성만 된 그룹은 "미확정" 태그
- 휴가그룹 추가 모달: 그룹명 필수 (밸리데이션) + 메모 (optional)
- 추가 후 상세 페이지로 이동

**휴가그룹 설정 탭** (= 휴가 설정 탭):
- 휴가그룹명만 입력해도 우측 휴가설정 리스트의 체크 표시 켜짐
- 3종 설정 (연차 제도 / 연차 정산 기준 / 연차 외 휴가 제도) 각각 [추가] 버튼:
  - 모달에서 선택 → 추가
  - 추가된 항목 클릭 → 상세 모달
  - X 버튼 → 항목 제거
  - **확정 후 연차 제도 X / 정산 기준 [추가] 비활성화 + 툴팁**. 백엔드도 연차 제도·정산 기준·회사 변경 시 BadRequest
  - ⚠️ **연차 외 휴가 제도는 확정 후에도 추가/제거 가능** (2026-11-02 검증 — 이전 KB의 "저장 항목 전부 제거 불가"는 outdated)
  - 확정 휴가그룹은 이름/메모만 추가 수정 가능. 삭제는 구성원 이력 있으면 불가(근무그룹과 동일), 항상 soft delete
  - 복제 기능 있음(2026-06): 본체 + 연차 외 휴가 매핑, "(copy)" 이름, 임시저장. 구성원은 미복제
- 연차 외 휴가 제도는 **여러 개 동시 선택** 가능 (다른 둘은 단일?)
- 저장 동작:
  - 밸리데이션 통과 시 즉시 저장 + 모달
  - 밸리데이션 실패 시 그 위치로 스크롤
  - **최초 저장 시 자동으로 다음 탭으로 이동** (근무그룹과 동일 패턴)
  - 저장 활성 상태에서 다른 탭 클릭 → 저장 확인 모달

**구성원 설정 탭** (근무그룹과 100% 동일 패턴):
- 검색 필터: 휴가그룹 소속 기간, 키워드(성명/사번), 조직, 회사, 활성 여부
- 구성원 변경 모달 (좌측 검색 ↔ 우측 그룹 소속, >>/<</>/< 이동)
- **변경일 지정**: 초기값 = 당일. 기존 그룹 없으면 입사일과 연차기산일 중 작은 값. **마지막 근무 마감일 이전 변경 불가**
- 추가된 구성원은 리스트 상단 노란색 배경

가장 복잡한 탭. 4개 핵심 액션:

#### 연차 자동생성 (L979–987)

- 그리드 좌측 체크박스로 대상자 선택 → [연차 자동생성] 버튼 활성화
- 모달에서 연도 선택 (이전/이번/다음 연도)
- 이미 생성된 연차 없는 대상자만 → "선택한 구성원들의 연차를 생성하시겠습니까?" 확인 → 저장
- 이미 생성된 대상자 포함 시 → 해당 대상자의 '부여일수', '사용일수' 리스트 표시 → 확인

#### 연차 조정 (L989–1014)

체크박스 선택 후 [연차 조정] 버튼 → 조정 페이지로 이동

**1년 미만 연차의 사용 시작일 입력 가능**:
- 다음보다 이전 → 밸리데이션:
  - 입사일
  - 연차기산일
  - 귀속연도의 1월 1일
- 사용 종료일과 같거나 이후 → 밸리데이션
- 기존 사용 시작일 이후 → 밸리데이션

**조정일 필드**: 지급/차감 옵션 + 조정일 입력. 변경 시 [적용] 버튼 활성화

> ⚠️ **기산일 검증 비대칭 (2026-07-10)**: 위 사용시작일 밸리데이션은 **어드민 프론트에만** 존재 (`ad:...annual_leave_summary_record_tab/edit/index.tsx:305–362`). 백엔드 조정 API는 포맷/역전/귀속연도만 검증. 기산일을 사후에 입사일 이후로 바꾸면 기존 행(useStaYmd=입사일)이 미변경 상태여도 에러로 잡혀 **조정 전체가 봉쇄**되는 반면, 사용/마감/정산은 기산일을 참조하지 않아 정상 동작. 상세: `_learnings/2026-07-10-anl-base-ymd-consistency-gap.md`

**[일괄 조정]**: 지급/차감 + 조정일 + 사용 시작일 일괄 입력

**적용 흐름**: [적용] → 조정사유 입력 → 적용
- 메시지: "ㅇㅇㅇ님 등 n건의 연차를 변경합니다."
- 적용 후 [부여 내역] 버튼에 **red dot** 표시
- [부여 내역] 클릭 → 부여 내역 화면 (조회기간 조정 가능, 디폴트 = 1년 전부터)

#### 연차 정산 (L1015–1029)

[연차 정산] 버튼 → 정산 / 정산 취소 선택:

**정산 처리**:
- 휴가그룹의 연차 정산 기준 설정에 따라 처리
- **귀속연도 단위로 처리**, 1년 미만 연차는 **합산 처리**
- 동일 귀속연도의 1년 미만 / 연차는 **각각** 정산/취소 가능
- 정산 결과가 컬럼에 표시, 잔여 컬럼 초기화

**정산 취소 처리**:
- 다음 귀속연도 연차가 정산된 경우 → 취소 불가
- 다음 귀속연도 잔여가 이월분보다 적으면 → 회수 불가 (에러)
- 다음 귀속연도 잔여가 충분 또는 이월분이 마이너스 → 회수됨
- 회수된 이월분은 정산취소 연도의 잔여로 반환

**자동 생성과 연계**: 전 귀속연도 정산결과 이월분이 있는 경우, 자동생성 시 부여 컬럼에 표시

### C-2. 연차 외 휴가 보유현황 탭 (L1031–1091)

조회 + 정산 + 수동 지급 + 삭제:

#### 지급 내역 화면

[지급 내역] 버튼 → 지급/차감 내역 화면 (조회기간 조정, 디폴트 1년 전부터)
- 표시 단위 설정 가능 ([더보기] 버튼) → 일/시간 컬럼 분기

#### 연차 외 정산 (L1054–1067)

**정산 방식 3가지**:
- **보상**: 정산 결과의 보상 컬럼에 추가, 잔여 = 0
- **이월**: 정산 결과의 이월 컬럼에 추가, 잔여 = 0
  - 이월 시 휴가 사용 종료일 선택 가능 (선택한 휴가 귀속연도 다음 해 1월 1일부터)
- **소멸**: 정산 결과의 소멸 컬럼에 추가, 잔여 = 0

**정산 취소**:
- 이월로 정산한 휴가를 이미 사용했다면 → 정산 취소 시 에러 모달

#### 삭제 (L1051–1052)

체크박스 선택 후 삭제. 다음은 삭제 불가:
- 정산 완료 건
- 사용분을 다른 휴가로 이관할 수 없는 건 (동일 유형 휴가 잔여 < 사용)
- 체크박스 클릭 시 [연차 외 정산] / [수동휴가지급] 버튼은 비활성화

#### 수동 휴가 지급 (L1068–1090)

**직접 입력 등록**:
- 입력 필드: 휴가 종류 / 지급 대상 / 귀속연도 / 지급 시간 / 사용 시작일/종료일
- **지급 단위 = 시간만 가능** (의도된 설계):
  > 일 단위로 입력하면 모호함이 발생함. 소정근로시간이 회사/사람마다 달라서 "1일"이 8시간일지 7시간일지 명확하지 않음. 시간 단위로 강제해서 항상 정확한 양을 입력하도록 함
- **지급 대상 의존성**: 휴가 종류 먼저 선택 후 활성화. 마우스 오버 시 "휴가 종류를 먼저 선택 후 지급대상을 선택합니다."
- 휴가 종류 선택 시 해당 휴가를 지급 가능한 구성원만 표시 (한 번에 다중 선택)
- 적용일 디폴트 = 당일
- 필수 입력 모두 채워야 [적용] 활성화

**엑셀 파일 등록**:
- 양식 다운로드 → 엑셀 작성 → 업로드
- A~F열 빈값 또는 포맷 오류 → 행별 밸리데이션 다이얼로그
- 통과 → 총 데이터 건수 + 휴가별 지급 건수 다이얼로그 → 확인 시 업로드
- 성공 시 보유현황 탭 데이터 갱신 + [지급 내역] red dot

**사용자/매니저 화면 가시성 (2026-05-15 갱신)**:
- 수동 부여한 연차 외 휴가는 **사용일수와 상관없이 귀속년도 기준**으로 사용자/매니저 화면에 조회됨
- 귀속년도 내 동일 휴가 여러 개 부여 시 → **개별 기한으로 상세정보** 확인 가능
- 매니저 측 동작은 `KB:product/user-member-view.md` § "연차 외 휴가 (수동 부여 휴가) 테스트" 참조

### C-3. 연차 사용 현황 탭 (L1092–1153)

조회 + 연차 수동 등록 (직접/엑셀):

#### 연차 수동 등록 (관리자 등록 휴가)

**직접 입력**:
- 필수 입력 검증
- 휴가 유형 입력 → 등록 대상 + 휴가일 disabled 해제
- 휴가일 입력 → 선택한 범위의 날짜만큼 사용 시간 입력 항목 노출
- **휴가 사용 시간 밸리데이션 7종**:
  - 차감시간 미입력
  - 차감시간이 30분 단위 아님
  - 시작시각 미입력
  - 종료시각 미입력
  - 시작 = 종료
  - 시작 > 종료
  - (종료 - 시작) < 차감시간

**저장 결과 분기 (3가지 시나리오)**:
| 시나리오 | 모달 |
|------|------|
| 전부 신청 가능 | 모달 닫힘 + 테이블 반영 |
| 전부 신청 불가 | 확인만 가능한 모달 |
| 일부 신청 가능 | 이어서 진행 가능한 모달 |

**이어서 진행 분기 (3가지 케이스)**:
- 정상 + 유효성 실패 혼합 → [이어서 진행]
- 정상 + 연차 부족 혼합 → [제외하고 등록]
- 연차 부족만 (1년미만 제외) → [초과 사용으로 등록]
  - 💡 등록 사용시간 > 연차 잔여 + 초과 사용 허용 안 함 OR 초과 사용 허용 제한 시간 넘김

**확정 시 메시지**: "~님 등 ~건의 수동 휴가등록을 합니다"

**엑셀 등록**: 위 직접 입력과 동일한 분기. 추가로 **근무 마감된 일자 포함 시 업로드 불가** + 안내 문구

### C-5. 연차촉진 (L1199–1245)

> **2025년 7월 9일 기준**: 연차촉진은 작업 삭제 기능이 없음 (확인됨, 추가 계획 없음). 휴먼컨설팅그룹 클라이언트는 프로덕션 체크리스트 안 함 (현 deep-dive에서는 무관).

**생성**:
- 시스템 전자문서에서 양식 생성 후 연차촉진 작업 생성
- 작업명과 비고만 수정 가능
- **연차 유형 = 연차** 선택 시: 현재년도 기준 대상자 기준 내 연차 미지급자 = 비대상, 나머지 = 대상
- **연차 유형 = 1년미만연차** 선택 시: 두 건의 연차촉진 작업 생성
  - 입사일/연차기산일 기준 근로기준법에 맞는 촉진기간
  - 근로기준법: 1년만근 3개월 전 (1차) + 만근 1개월 전 (2차, 1차 이후 발생분)
  - 지급된 1년미만연차의 기간이 만료되지 않은 인원이 대상 (생성여부 따라 비대상 분류 없음)

**상세페이지 - 4개 탭**:
1. **대상자 및 현황관리** (`employee_overview_step`)
2. **미사용 연차 통지 및 사용시기 지정 요청** (`unused_leave_notification_step`)
3. **사용시기 지정 및 통보** (`usage_period_assignment_step`)
4. **노무수령거부 현황** (`work_refusal_overview_step`)

**워크플로우**:
- 통지 → 사용자에게 연차촉진 문서 발송 (사용자 화면 연차촉진 화면에서 확인)
- 통지서/계획서 클릭 → 전자문서 열람
- 사용시기 지정 엑셀 업로드 가능
- 사용시기 지정 통보 → 문서 발송 + 노무수령거부 알림 안내문
- 노무수령거부 알림 = 시스템 > 알림설정에서 활성화

**노무수령거부 팝업 노출 조건** (L1239–1244):
- 공통: 전체 알림 받기 + 일반 알림 + 노무수령거부 상세 알림 모두 ON + 당일 미동의
- 웹 알림만 ON: 데스크톱 환경만 노출
- 모바일 알림만 ON: 모바일 기기만 노출
- 둘 다 ON: 항시 노출
- 둘 다 OFF: 미노출

**연차 사용 여부**: 지정 연차일에 **연차** 사용 시 "O" / **연차 외** 사용 시 "X" 표시 (연차만 카운트)

| 12시간 | 12 / 8 = 1.50 → **1.5일** |
| 16시간 | 16 / 8 = 2.0 → **2일** |

3. **연차 정산은 귀속연도 단위**, 1년 미만 연차는 합산 처리
4. **다음 귀속연도 정산 시 이전 정산 취소 불가**
5. **마감일 휴가 요청/승인/취소 모두 불가**
6. **정산된 휴가 요청/승인/취소 불가**
7. **연차 외 휴가는 사용자용/어드민용 이름 분리 가능**
8. **휴가 사용 시간 고정 설정 시 30분 단위 검증 비적용 + 근무계획 무관 사용 가능**
9. **휴가 일수 계산 = 분 / (일소정근로시간 × 60)**, 소수점 둘째자리 반올림
   - "일소정근로시간" = 일계획 `workTimeCd` > 근무그룹 `cenDdWorkTime` > 480분 (UseLeaveService.java:1117–1120, CenDdWorkTimeUtil#resolveWorkMinutes)
10. **사용자 출근 가능시간**: 시스템 기본 6시, 익일 고정출근 있으면 (익일출근 - 2시간)까지
11. **1년 미만 연차 부여방식**:
    - **선부여 (1건)**: 같은 사용기간으로 일괄 부여
    - **다건 분할**: 별도 사용기간/개수, 상세 모달로 확인
12. **연차촉진 = 시스템 전자문서 + 노무수령거부 알림** 통합 워크플로우
13. **휴가그룹 = 근무그룹과 독립** — 같은 구성원이 서로 다른 휴가/근무그룹 가능
14. **수동 휴가 지급 단위 = 시간만** (의도된 설계): 일 단위 = 모호함 (회사/사람마다 소정근로시간 달라 "1일"이 8시간일지 7시간일지 명확하지 않음)
15. **어드민 직접 등록 휴가**: `AdminDirectLeaveDialog` 별도 다이얼로그, 신청서 워크플로우 우회

## 알려진 제약 / 임시 동작

- 연차촉진 작업 **삭제 기능 없음** (2025.07.09 기준, 추가 계획 없음 — 확인됨)
- 휴먼컨설팅그룹 클라이언트는 연차촉진 프로덕션 체크리스트 진행 안 함
- 수동 휴가 지급의 단위는 **시간만 지원** — **의도된 설계**. 소정근로시간이 회사/사람마다 달라 일 단위가 모호함을 일으키므로 시간 단위로 강제
