# 직책 설정

> **메뉴** 근무관리 › 모듈 설정 › 직책 설정  
> **URL** `/attendance/module_setting/duty_setting`  
> **원본** `product/_legacy/admin-system-entry.md`

*원본 섹션: #2-3. 직책 설정 (L52–71)*

## 인사 연동 모드

- 인사 모듈 연동 시 → 페이지 상단 연동 정보 + **readonly 조회만 가능**

## 직책 리스트 표시 룰

| 모드 | 노출되는 직책 |
|------|------|
| **근무 단독 모듈** | 클라이언트의 모든 직책 |
| **인사 + 근무 연동 중** | **인사 발령이 있는 직책만** + 인사 연동 이전 근무에서 추가한 직책 |
| 공통 | 퇴직자는 미조회 |

> 인사에서 새 직책 추가 → 인사 발령 없으면 근무 모듈에 미연동

## 직책 세부 조회

- 동일 직책을 여러 조직에 본발령 + 겸 소속 시 → **툴팁으로 표시**

## 화면 구성 (2026-11-05 코드 확인, `ad:src/components/attendance/module_setting/duty_setting/`)

- 헤더: "직책 설정" + **[직책 생성]** (인사 연동 중이면 비활성)
- 연동 안내: "조직-구성원 연동 중입니다. 연동 시스템에서 조직-구성원 정보를 수정해야 합니다." + "연동 구분: … | 마지막 연동 일자:"
- 목록 컬럼: 직책명 · 구성원 수 · 삭제(X) · 상세 + [순서 변경] 버튼(→ 드래그 후 [취소]/[저장])
- 상세(우측 패널 "직책 상세"): 직책명 입력 + 구성원 표(이름 · 사번 · 활성 여부 · 조직, 겸 소속 다수는 "OOO 등 N개" 툴팁) + [수정]→[취소]/[저장]

## 근무 자체 관리 모드 (인사 연동 X)

직책 수정/삭제/생성 가능:
- 신규 직책은 상단에 생성
- 직책명: **중복 불가, 최대 20자** — 프론트 검증 + 백엔드 재검증 (`ad:…/CreateDutyForm.tsx:49-60`, `UpdateDutyForm.tsx:120-133`, `be:service/setting/DutySettingService.java:201-209`)
- **구성원 있는 직책은 삭제 불가** — 삭제 버튼은 활성이고, 확인 후 서버가 거절 (`be:DutySettingService.java:225`)
- **(2026-11-05 신규 확인) 직책자 권한 그룹에 포함된 직책도 삭제 불가** (`be:DutySettingService.java:230`)
- 직책간 보기 순서 변경 가능

### 화면 메시지 (`ad:src/locales/ko/duty.json`, 백엔드)

| 상황 | 메시지 |
|------|------|
| 직책명 미입력 | "직책명이 없습니다." |
| 20자 초과 | "직책명은 최대 20자까지 입력할 수 있습니다." (백엔드: "직책명 최대 20까지 입력할 수 있습니다.") |
| 중복 | "이미 존재하는 직책입니다." |
| 수정 시 변경 없음 | "변경사항이 없습니다." |
| 생성 성공 / 수정 성공 | "새 직책이 생성되었습니다." / "직책 정보가 저장되었습니다." |
| 삭제 확인 | 타이틀 "삭제 요청", 본문 "[직책명] 직책을 삭제하시겠습니까?" |
| 삭제 성공 | "직책이 삭제되었습니다." |
| 구성원 있는 직책 삭제 | 타이틀 "삭제 실패" + "해당 직책에 속한 구성원이 있습니다. 구성원 관리에서 해당 구성원 다른 직책으로 변경한 후 삭제 가능합니다." |
| 직책자 권한 그룹 사용 중 삭제 | 타이틀 "삭제 실패" + "해당 직책이 직책자 권한 그룹에 사용되고 있습니다. 권한 설정에서 해당 직책을 제외한 후 삭제 가능합니다." |
| 순서 변경 성공 / 실패 | "직책 순서 수정이 완료되었습니다." / "순서 변경 실패" + 서버 메시지 |
