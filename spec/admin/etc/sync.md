> **메뉴** 근무관리 메뉴 외 — 인사관리·시스템 쪽에서 근무 모듈로 들어오는 연동
> **사용자** 어드민(인사·시스템 관리자)

## 1. 개요
인사 모듈과 시스템 모듈(계정관리)의 변경이 근무 모듈 구성원에 어떻게 반영되는지 정리한 페이지입니다. 연동 설정 자체는 근무관리 메뉴 밖(인사 데이터 연동 설정, 시스템 › 계정관리)에서 하며, 결과로 만들어진 근무 모듈 구성원 데이터는 [구성원 정보](../module-setting/member-information.md)에서 확인합니다.

## 2. 화면 구성
| 영역 / 탭 | 구성 요소 | 설명 |
|---|---|---|
| 인사 데이터 연동 설정 › 근무관리 | 연동 / 연동 안함 설정, [재연동] | 인사 ↔ 근무 구성원 연동 전체 설정 |
| 시스템 › 계정관리 | 계정 활성 / 비활성 | 계정 상태 변경이 근무 모듈에 전파 |

## 3. 기능 상세
### 3.1 인사 모듈 ↔ 근무 모듈 전체 연동 설정
| ID | 기능 | 상세 동작 | 조건 · 예외 |
|---|---|---|---|
| A-ETC-SYN-01 | 연동 해제 | 연동 → 연동 안함 변경 시 근무 모듈 구성원과의 연동 해제 | 이후 조직·구성원·직책은 근무 모듈에서 자체 관리. 해제 시점의 구성원 활성/비활성 상태는 그대로 유지 |
| A-ETC-SYN-02 | 연동 설정 | 연동 안함 → 연동 변경 시 '연동 구성원'이 근무 모듈 구성원과 연동 | — |
| A-ETC-SYN-03 | 재연동 | [재연동] 버튼 클릭 시 인사 데이터를 근무 모듈에 다시 일괄 반영 | 직책 → 조직 → 회사 → 구성원 순으로 반영. 인사 데이터에 없는 조직은 비활성 처리, 구성원의 겸직 등 부가 소속은 다시 적재 |

### 3.2 실시간 연동 (연동 중일 때)
| ID | 기능 | 상세 동작 | 조건 · 예외 |
|---|---|---|---|
| A-ETC-SYN-04 | 인사발령 확정 반영 | 인사 모듈에서 인사발령 확정 시 근무 모듈에 즉시 반영 | — |
| A-ETC-SYN-05 | 휴직/퇴직 발령 | 근무 모듈 구성원 비활성 | — |
| A-ETC-SYN-06 | 입사 발령 | 근무 모듈 구성원 추가 | — |

### 3.3 시스템 모듈 계정 상태 변경
| ID | 변경 | 인사 ↔ 근무 연동 중 | 연동 안 함 |
|---|---|---|---|
| A-ETC-SYN-07 | 활성 → 비활성 | 근무 모듈 구성원 비활성 + 모듈별 상태 비활성 | 동일 |
| A-ETC-SYN-08 | 비활성 → 활성 | **근무 모듈 활성 상태 변경 안 됨** (인사 발령으로만 활성화) | 근무 모듈 활성 + 모듈별 상태 활성 |

## 4. 정책 · 비즈니스 룰
1. **인사 발령 우선**: 연동 중에는 계정을 다시 활성화해도 근무 모듈 구성원이 활성화되지 않으며, 인사 발령으로만 활성화됩니다. 근무 모듈에서 임의로 활성화할 수 없습니다.
2. 계정 비활성화는 연동 여부와 관계없이 근무 모듈에 그대로 반영됩니다 (비대칭).
3. 연동 중에는 조직·직책이 인사 모듈 기준이며 근무 모듈에서는 조회 전용입니다.
4. 인사 발령이 없는 직책은 근무 모듈에 연동되지 않습니다.
5. 별도로, 외부 출퇴근 기록(세콤) 동기화 기능이 있으며 외부 기록을 쓰는 근무그룹에 적용됩니다.
6. 연동을 해제해도 기존 근무 모듈 구성원의 활성/비활성 상태는 바뀌지 않습니다.
7. 연동 중 여부에 따라 구성원 정보·조직 설정·직책 설정 화면 상단에 "조직-구성원 연동 중입니다. 연동 시스템에서 조직-구성원 정보를 수정해야 합니다." 안내와 연동 구분·마지막 연동 일자가 표시됩니다.
8. 인사 모듈의 [재연동]은 근무 모듈 전체 재연동(직책·조직·회사·구성원)을 실행합니다. 회사 코드 변경 등 개별 이벤트가 어긋난 경우 재연동으로 회사 정보까지 다시 맞출 수 있습니다. (기획 확인 2026-11-05)
